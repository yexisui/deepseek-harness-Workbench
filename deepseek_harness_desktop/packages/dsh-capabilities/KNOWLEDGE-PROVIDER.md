# 外部知识库独立模块与接入契约

更新：2026-10-26。`external-knowledge` 是功能中心独立能力，拥有 `knowledge-retrieval` 组件和 `search-knowledge` 动作。各岗位将它作为平级能力关联；不再放入需求或文档能力的组件组合。正式运行环境尚未登记真实提供方，显示“待接入”。合成测试提供方只存在于测试及隔离演示。

## 助手侧接入

宿主创建唯一的 [KnowledgeAccess](src/host/knowledge-access.ts)，统一处理岗位授权、资料范围、撤权、取消和历史证据；其内部 [KnowledgeService](src/host/knowledge.ts) 负责提供方协议和来源归一化。业务不能绕过权限网关直接调用提供方。

| 执行路径 | 接入行为 |
|---|---|
| 普通聊天及新建/复制岗位 | 运行层按岗位绑定登记 `search_knowledge({query})`，无需岗位名称/ID白名单；模型按需调用 |
| 需求模板生成、修改、问答 | 本次任务选择范围，生成前检索，仍校验逐字引用并保留审阅与版本流程 |
| 原需求分析流程 | 岗位配置范围后，在分析模型调用前通过共享网关加入参考资料 |
| 智能文档 | 用户启用外部资料时，采用岗位范围，文档P引用与外部K引用分开保存 |
| 会议纪要 | 仅最终纪要生成使用岗位范围；不改录音、ASR和原文时间轴，外部资料不能冒充会议原话 |
| 开发助手 | 原执行路径通过共享生成包装；代码引擎通过宿主 guidance 注入资料，传递当前消息和取消信号，结束后释放使用标记 |
| 可导入能力包 | 在具备模型权限并持有真实岗位上下文的模型调用中接入；管理页试运行不假冒某个岗位授权 |

通过工作台界面创建助手，只需关联模块、选择范围并保存，新对话直接生效。普通聊天未选范围会提示选择，不自动查询全库；专用流程没有范围时沿用本地业务。需求任务可另选范围，但不能超过岗位已限制的集合、产品和项目。服务连接共用，岗位范围、任务证据分别保存。

新增独立执行器应在服务端调用同一个网关的 `search` 或 `generate`，传入可信 taskId、roleId、roleVersion、authorityAt 与 AbortSignal。仅创建岗位无需开发；开发新的执行器仍须遵守契约和通过接入测试。不能将“卡片可以关联”等同于第三方任意执行器已经兼容。

## 提供方侧接入

宿主插件实现 [KnowledgeProvider](src/core/knowledge.ts)，通过已有 Cordis 服务登记 `knowledgeProvider`：`ctx.provide('knowledgeProvider', provider)`。使用稳定的提供方ID，宿主在每次调用时读取该服务。类型源文件在本仓库，无新增npm SDK。

- `id`：稳定标识。岗位/任务范围同时保存providerId，更换服务后需重新选择范围，不能把旧集合ID当作新库授权。
- `status()`：configured、verified、label、message、collections及可选checkedAt。只列当前连接允许的资料集；配置存在不代表连接检测成功。
- `search({query,limit,scope?,context?},signal)`：只读检索；scope含collectionIds及可选providerId/product/project；context由服务端创建，包含任务、岗位、配置引用和执行类型。
- 来源包含稳定id、documentId、chunkId、title、text、collectionId，可选locator、url、version。返回范围外来源会被宿主拒绝。

提供方适配器维护自己的地址、凭据、连接检测及数据库访问控制；复用宿主服务端设置与凭据遮挡。密钥、鉴权头及带凭据链接不进入状态、来源、岗位配置或普通日志。宿主状态只返回白名单字段，来源链接只接受无用户名密码的HTTP(S)。业务过滤不能替代提供方ACL。

按实际服务协议实现查询向量化、检索、过滤与字段转换。当前预留接口不等于可以把任意向量数据库地址直接填入使用。无结果返回空数组，错误应脱敏；不能自动放宽范围或回退到其他产品。宿主不自动上传任务文件、不创建索引、不做远端删除。

## 取消、证据和管理API

状态等待最长8秒，单次检索最长60秒；传递取消信号并停止等待不响应取消的适配器。远端是否真正中断由适配器实现，宿主不采用迟到结果。执行前后检查授权，全局停用会取消正在使用知识库的调用及已接入生成步骤；无外部引用的本地业务可继续。

每次最多8条、每条最多6000字；身份由提供方、集合、文档和片段组成，去重并保存SHA256、检索时间及来源版本。记录位于用户数据的 `capabilities/knowledge` 目录，按任务分文件，界面使用情况展示最近100条；普通工具输出也进入原对话历史。专用对话分叉复制证据、不复制运行连接，保留原记录。需求流程另保留被采用的证据与版本关联。引用可核对不代表模型结论必然正确。

以下地址都沿用工作台认证与来源检查：

- `GET /api/capabilities/knowledge/status`：提供方及模块状态。
- `POST /api/capabilities/knowledge/search`：独立管理页检索试用，接收query和scope，不接受客户端伪造岗位上下文。
- `GET /api/capabilities/knowledge/history?taskId=...`：任务证据；无taskId返回最近100条实际记录。

管理页试用不调用模型、不建立需求任务。服务设置唯一入口为功能中心“外部知识库”；其他业务页仅提供跳转和本次范围选择。没有提供方时禁用检索，不展示虚假连接表单。

## 旧数据兼容

存储初始化进行一次幂等迁移：先核对原嵌入检索的有效授权，再增加独立绑定；原本无授权、排除动作、全局停用或撤权不自动扩权。内部能力/岗位历史配置作兼容映射，保留原版本号、preset、其他配置和名称；任务内容、历史证据、文档与凭据不改写。旧草稿保留，新的独立关联遵循取消/保存。

已开始任务仍使用原内部配置引用；新增加的岗位授权不会扩展旧任务。全局撤权持续生效。旧管理链接的 `config:knowledge` 转向独立模块；旧文档状态地址保持。旧 `documentKnowledge` 服务在没有新提供方时兼容智能文档，其协议无资料集，不支持新范围选择；新接入应实现knowledgeProvider。

## 验收边界

自动化覆盖独立登记、旧授权迁移、随机岗位实际工具调用、范围隔离、提供方切换、取消与撤权、历史持久化/分叉、需求与文档/会议消费及共享UI。代码引擎验证宿主guidance契约。合成端到端演示用于确定宿主行为，不代表已连接真实RAG，也不评价真实模型的召回和回答质量。

有实际服务后补适配器与唯一配置表单，验真实鉴权、连接检测、集合失效、空结果、取消、召回质量和跨助手完整业务。保留模型与RAG两个独立服务的故障区分。
