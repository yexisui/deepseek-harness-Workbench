# 制作与分发能力包

能力由开发者在外部工程制作。工作台只提供“导入能力”和“导出能力”，接收方无需创建能力或手动发布草稿。

## 1. 准备交付目录

复制本包的 `examples/text-tool` 目录作为起点。修改作品标识、名称、作者、许可、动作和已构建代码；只把可分发文件放进交付目录。首次使用可直接导出这个示例，不需要安装开发依赖。

```text
my-ability/
  capability.json
  runtime/main.cjs
  resources/       （可选）
  docs/            （可选）
```

根目录清单描述一个作品，`runtime` 放执行构建文件，`resources` 放资源，`docs` 放说明。工程源码、依赖安装目录和私人配置保留在开发工程中。

清单格式见示例 `capability.json`。关键规则：

- `schema` 为 `1`，`protocol` 为 `dsh-worker-v1`；接收端必须提供这一协议。不支持的协议会在导入前被拒绝。
- `id` 使用稳定的反向域名式标识，例如 `com.my-company.my-ability`。名称可以重复，标识不能冒用其他作品；更名不需要换标识。
- `version` 使用三个非负整数，例如 `1.2.0`。每次改变交付内容都提升版本；同标识同版本不同内容不能覆盖。
- `permissions` 必须包含 `node`。如果调用工作台模型，再加入 `model`。
- 每个组件有独立 `id`、中文 `name`、`runtime/*.cjs` 入口和动作清单。组件内动作标识要稳定，最多 10 个动作；每包最多 20 个组件。
- `files` 显式列出所有交付文件。开发目录可以使用 `auto`，导出器会计算 SHA-256；ZIP 中必须已经填入摘要。
- 一包最多 500 个交付文件和 64 MiB。文件路径必须相对、唯一，不能有符号链接、上级目录、设备名或私人配置文件。

## 2. 实现执行入口

```js
exports.execute = async ({ action, input, api }) => {
  if (action === 'summarize') return api.model(String(input))
  if (action === 'uppercase') return String(input).toUpperCase()
  throw new Error('未声明的动作')
}
```

入口采用 CommonJS 的 `execute` 导出。`action` 是本组件动作标识；`input` 是使用者输入的文本或主动选择的 JSON。返回值必须可序列化为 JSON，最大 512 KiB；界面将展示结果。岗位工具同样调用此入口，但使用岗位绑定的固定能力版本。

`api.model(prompt)` 复用接收方工作台模型账户，密钥不会传给组件。此方法需要清单声明 `model`；使用者在能力设置中选择已配置模型，留空使用工作台默认模型。每动作最多顺序调用 10 次，每次输入最多 32,000 字符。没有模型时，能力导入为停用并直接进入配置。

`api.resourceRoot` 是当前不可变版本的资源目录。第三方 JS 库应在外部工程中打包进 CJS 构建产物；运行相对依赖时，也必须将这些文件列入清单。不要依赖制作者机器的 `node_modules`、绝对路径、环境变量或未列入清单的文件。导出器不会安装依赖、执行构建脚本或运行组件预览。

这是**受信任的本机 Node.js 代码协议**。Worker 不是安全沙箱，组件具有本机代码访问能力；动作声明用于工作台授权路由，不能隔离恶意代码。导入前会清楚展示这一点。组件不要启动独立进程、守护进程或脱离调用生命周期的任务。停止/超时会终止本次 Worker 和通过工作台代理的模型调用，不能撤销代码已经完成的文件或网络操作。执行上限 180 秒，同一工作台最多并行 4 个动作，Worker 的 JS 堆内存设有限额。

此协议的构建组件按调用加载，不需要安装 Cordis 插件或重启。完整 Cordis 插件、浏览器扩展、原生驱动不属于这种构建组件；仍由各自真实管理入口安装。内置会议、需求、开发工作区随应用交付，不能作为独立外部作品导出；导出来源列表只显示有完整执行包的版本。

## 3. 导出、导入和使用

1. 制作者先在开发工程完成构建与验证，再打开能力中心的“导出能力”。
2. 来源选择“本地开发目录”，选择交付文件夹，核对预览后点击“导出能力包”。
3. 把生成的 ZIP 交给使用者。接收端选择“导入能力”，核对作品、组件、动作和权限，确认信任制作者。
4. 配置齐全时点击“导入并启用”；缺模型时点击“导入并配置”，配置后保存并启用。
5. 在能力设置页直接运行动作，或在岗位编辑中添加能力、发布岗位，并从该岗位创建新会话。导入本身不会执行任务或替任何岗位授权。

从已安装能力导出时选择完整发布版本。未发布草稿不会被误当作发布版本；发布版本若含本地编辑，导出器会生成新的派生作品标识并记录原版来源。模型选择、服务密钥、岗位绑定、聊天及任务结果都不会进入 ZIP。开发者仍需自行检查代码和资源，避免将秘密写死在构建产物中。

## 4. 更新与移除

导入新版会显示变化、保留旧构建与版本。未发布草稿可以保留，或先备份再替换；备份在能力设置的来源与回退中恢复。默认不改岗位绑定，可明确勾选让指定岗位的新会话采用新版；岗位未发布草稿继续保留。

重复导入相同标识、版本和内容会打开原能力。回退会新建采用旧代码的本地版本并停用，检查后再启用；不会静默改动岗位、草稿或历史结果。撤销过的动作不会恢复到旧会话，需要重新选择合适的能力版本并创建会话。

垃圾桶把能力移到回收站并停止相关执行；恢复保持停用。仍被岗位草稿或任何历史版本引用的能力不能永久删除。受管构建按内容摘要保存，暂不自动清理仍可能用于历史追溯的构建文件。

## 5. 验证与定位

导出检查的是清单、文件摘要、路径和协议。确认信任并导入后，系统在独立 Worker 中检查执行模块是否可加载及是否导出 execute；最多等待 5 秒，不调用业务动作。模块顶层初始化代码会在这一步运行，开发者应将实际任务操作放在 execute 中。导入后的“已就绪”表示文件与执行适配器准备完成；模型可连接、任务能成功必须通过实际运行确认。任务结果保存在接收方能力数据目录，关闭或重启不会自动重放未完成任务。

遇到问题先看导入窗口或任务结果中的具体错误。旧的前端或服务不认识此协议时，升级至包含能力包分发功能的工作台并正常重启；不要手工把包内文件复制进全局插件目录。
