## 1. 已交付的使用流程

在岗位中选择“智能文档助手” → 打开或拖入 DOCX → 左侧编辑 → 右侧选择选区、章节或全文正文进行提问 → 请求 AI 局部改写 → 查看原文与建议 → 采用 → 保存或另存为。

岗位卡片、顶部入口、新对话、最近文档和能力编辑使用现有工作台管理框架。右侧问答栏可以收起、拖动边界调宽；键盘聚焦分隔条后可用左右方向键调整。主题跟随工作台，窄屏上下排列。

文档解析、编辑和工作副本暂存在本机。AI 使用已经配置的默认或指定模型；凭据由现有服务端设置持有。问答会向该 API 发送问题和所选范围正文，因此编辑可离线，外网 AI 仍需联网。本轮没有安装本地模型或 Office 文档服务器。

## 2. 采用的技术与能力组织

| 部分 | 实际实现 |
| --- | --- |
| 编辑器 | @docx-editor.dev/core、react、i18n 2.28.0 的开源部分；本机同源 iframe 提供 ESM、CSS、WASM |
| 编辑运行时 | 复用既有 Electron；中文及西文字体读取本机 Windows 安装字体，不重新分发系统字体 |
| AI 修改 | dsh-office-toolkit 0.3.32 公开插件入口验证候选 DOCX，再经编辑器的选区粘贴命令采用，保留原生撤销 |

| 岗位与能力 | 1 个“智能文档”能力、1 个 document-editor 组件、1 个内置“智能文档助手”岗位；动作是编辑、问答、改写 |

原先的五能力规划保留为路线图：智能文档、知识库问答、模板生成、PDF/OCR、批量文档处理。本次完成第一项和知识库接口；后三项不属于本轮实现，知识库独立能力在选定实际服务后再落地。

## 4. 数据保存与 AI 修改规则

- 打开原文件后建立独立工作副本；自动暂存不覆盖原件。用户点击“保存”或“另存为”才写入选择的目标文件。
- 原文件打开后若被其他程序改变，原位保存会提示冲突；可另存为，不能静默覆盖外部修改。取消文件对话框不会写文件。
- 切换岗位保留各自文档与未发送问题；切换页面保留编辑器和撤销记录。新文档会话不会删除历史工作副本。工作台重新启动后可从历史打开已暂存文档，重新另存为文件。
- 工作副本采用修订号和串行保存；保存过程中继续输入不会误标为已保存。新的字节文件写好且索引成功后才切换当前修订。
- AI 基于当前编辑器快照，包含尚未写回原文件的编辑；全文仅含正文和表格，不包含页眉页脚。超过 8 万字时提示选章节或选区，本轮不发送模型，也不偷偷截断。
- AI 首版支持一处段落内部文字替换；展示原文、建议和理由，必须由用户点击采用。候选副本通过 toolkit 公开工具生成，并核对非正文 ZIP 部件完全未变。
- 采用时再次检查工作副本修订、编辑器修订、段落和原文唯一性。生成后正文变化，或者原文重复无法唯一定位，均要求重新生成。
- “撤销刚才的 AI 修改”仅撤销仍是最后一处编辑的 AI 操作；之后已有人工修改时提示使用编辑器逐步撤销，避免丢失人工输入。
- 文档和知识库片段作为资料，不把其中要求执行代码、读取其他文件或改变权限的内容当作用户指令。

## 6. 离线包与空间实测

- 交付包：`offline-delivery/DeepSeek-Workbench-Offline-2026.10.13-r10-win-x64.zip`。
- ZIP 约 509.3 MiB，完整程序解压约 1451.5 MiB。这是整个工作台，不是文档模块单独体积。
- 相比 r9，程序资源增加 54,893,039 字节，约 **52.4 MiB**；其中文档编辑器 JS/CSS/WASM/许可证合计 4,868,484 字节，约 **4.6 MiB**。其余主要为 toolkit 及其运行依赖；差额包含同次构建变动。
- SHA256：`a6d5efb679b0f8423abc6f8cbc059cc8b73cd459a3f71bfb122cd0fefe5e1ef1`。
- 包内仅有 offline/，没有第二套根启动入口；ZIP、程序、文档及凭据不进入 Git。
- 打开文档时还会使用字体、图片、分页缓存和工作副本空间。没有对实际桌面完整进程进行内存基准测试，不能用磁盘增量替代内存结论。

关闭工作台后按现有“一键部署”流程使用此 ZIP；本机已安装当前开发构建。启动后可在岗位选择中找到“智能文档助手”。

## 7. 查验步骤与后续入口

1. 重启工作台，选择“智能文档助手”，打开一份普通 DOCX；检查顶部入口与岗位卡片联动。
2. 手工修改文字、另存为副本，再打开副本；核对表格、图片、页眉页脚与常用字体。
3. 选中一段并提问，再切换章节/全文；确认使用工作台已有模型，回答依据定位可用。
4. 请求一处局部改写，核对差异后采用，保存；再测试撤销。生成建议后先手工编辑，再采用旧建议，应提示重新生成。
5. 切到其他岗位再回来，确认文档和未发送问题保留；点击新对话后，可从历史打开旧文档。
6. 外部资料库应显示尚未接入。选定服务后，按源码中的 [DOCUMENT-KNOWLEDGE.md](../../deepseek_harness_desktop/packages/dsh-capabilities/DOCUMENT-KNOWLEDGE.md) 实现适配器，复用服务端凭据管理。

### 2026-10-13 历史按当前对话隔离与移除（Codex）

用户明确历史只属于当前对话，新对话不继承。新增持久化 conversationId，同一对话打开的多份文档共享该标识；新会话无论从何入口创建均重置文档状态并清除岗位自动恢复指针。历史和空白页最近记录都按当前对话筛选；打开旧记录恢复它自己的所属对话。旧数据无标识时以记录 ID 视为独立对话，不猜测合并或删除旧资料。

每条历史右侧新增垃圾桶移除按钮，调用已有软移除操作，停止该记录生成；当前记录被移除后清空编辑区，保留其他记录。不删除用户原始 Word 文件。
