## 1. 要做成什么

在现有 DeepSeek Harness 工作台内增加智能文档功能，让用户直接打开和编辑 Word，在文档旁边提问、理解内容，并让 AI 提出局部修改，用户采用后保存。

核心体验：**打开文档 → 人工编辑或选择内容 → 侧栏提问/提出修改要求 → 查看修改建议 → 采用 → 保存 Word。**

首期以 DOCX 为正式验收重点，尽量保留原排版。编辑引擎不能保证所有 Word 特性完全无损；复杂表格、字体、编号、嵌入对象等需要代表性文件验证。首期不承诺 Excel/PPT 的完整 AI 编辑、多人协作、宏或“万能悬浮球”。

## 2. 技术路线与职责

| 部分 | 采用方案 | 负责内容 |
| --- | --- | --- |
| 文档界面 | Fylar Office Editor | 显示、分页、人工编辑、文字选择和文档导出 |
| 文档操作 | dsh-office-toolkit | 读取结构、局部修改 DOCX、模板填充及文档生成 |
| AI 服务 | 工作台现有模型路由与设置 | 问答、解释、摘要、生成修改建议；复用既有账号和取消/执行机制 |
| 文档协调层 | 工作台新增适配与文件服务 | 当前内容快照、修改范围、候选文件、采用/撤销、保存和失败处理 |
| 独立工具 | 模板、PDF/OCR，后续批量与知识库 | 独立入口，共用文件、任务和结果能力；结果可回到主编辑区 |

P0 固定版本为 Fylar 插件 **0.1.5**、dsh-office-toolkit **0.3.32**。后续正式集成保持版本可追踪，不在普通启动时自动升级。Fylar SDK 属于专有商业软件，发布包能启动不等于商业部署授权已经核实。

## 3. 能力中心与界面布局

能力中心按 **首期 3 个、完整规划 5 个** 组织。摘要、翻译、润色等作为能力内部动作，不各自增加能力卡片。

| 能力 | 包含内容 | 交付顺序 |
| --- | --- | --- |
| 智能文档 | Word 编辑、选区/全文问答、摘要、解释、AI 局部修改 | 首期核心，P1–P2 |
| 模板生成 | 选择模板、填写字段、生成新 Word、回到编辑区 | 首期基础版，P3 |
| PDF 与 OCR | PDF 阅读、文字提取、扫描件/图片识别、校对与问答 | 首期基础版，P3 |
| 批量文档处理 | 多文件摘要、字段提取、模板生成、任务进度和结果列表 | 第二批，另行批准 |
| 知识库问答 | 接入实际知识库、检索问答、引用、材料入库与维护入口 | 第二批，另行批准 |

已有同类能力或文件搜索直接复用，不重复建设。每个能力可单独关联岗位，也可组合为一个文档助手。Fylar、toolkit、OCR 和模型服务属于组件或依赖，不按插件品牌额外拆能力卡片。

参考用户图片，主界面采用以下分区：

- **顶部：** 文件名、打开、最近、保存、另存为、AI 侧栏和真实保存状态。
- **左侧约 2/3：** Fylar 文档编辑区，保留其必要编辑工具；支持拖动调整宽度、收起侧栏。
- **右上：** 选中内容、大纲、提取文本，默认显示当前选区与所属章节。
- **右下：** 文档问答、修改建议、差异说明、采用/撤销、输入框。
- **文档工具入口：** 模板、PDF/OCR；后续加入批量与知识库，不把所有工具常驻堆在编辑区。

Word 采用原生文字/段落选区。矩形框选主要用于 PDF 页图、扫描件和图片，识别出的文字不能直接当作 Word 中的准确修改位置。窄屏折叠侧栏，保持正文可读。

## 4. 编辑、AI 修改和保存如何衔接

1. **取得当前内容。** 提问或生成修改前，从编辑器导出工作副本，必须包含尚未保存的人工修改，不能只读磁盘原件。
2. **定位修改范围。** 结合所选文字、段落/表格位置和上下文定位。重复文本不能直接全局替换；无法唯一定位时只展示建议。
3. **生成候选。** AI 生成结构化修改建议，toolkit 在工作副本上执行，保留原件与当前编辑内容。
4. **先看再采用。** 侧栏显示原文、建议和影响范围。用户采用前核对当前内容是否又发生变化，避免旧建议覆盖新输入。
5. **加载结果。** 采用成功后显示改后文档并标记未保存；加载失败恢复原工作内容。
6. **保存文件。** 用户点击保存才更新目标文件。处理导出失败、文件占用、外部修改和写入中断，不能先删除原件或提前显示保存成功。

人工编辑优先用引擎撤销。AI 候选重新加载可能重置原生撤销栈，因此另提供“撤销本次 AI 修改”，同时保护后续人工输入。内部副本由程序管理，不增加用户必须管理的版本、发布或备份流程。

文档与 OCR/检索内容仅作为分析材料，不执行其中夹带的指令。使用远端模型时，只发送本次需要的文字和上下文，不宣称整个 AI 链路都在本机。

## 6. P0 已完成什么、尚不能说明什么

已在独立目录完成一份合成 DOCX 的真实验证：

- Fylar 能打开文档，鼠标选区能读取；手动插入文字后可以导出。
- toolkit 基于手动导出的最新文件修改指定段落；该步骤只改变 word/document.xml，人工修改保留。
- 候选文件能重新打开、再次导出并重开；原始样本哈希保持不变。
- 样本中的表格、图片、混合加粗、页眉页脚和页码字段仍在；图片字节相同，页面尺寸与页边距保持。
- dryRun 不写输出；目标不存在的测试操作会报错且不写文件。

本阶段**没有调用大模型**，是脚本直接调用真实工具验证编辑链路；问答与自然语言修改仍在 P2。没有把完整 DSH 宿主集成、能力中心入口或正式安装包视为已完成。

发现的边界：Fylar “打开不改再导出”仍会重写 15 个 XML 部件并移除 3 个 customXml 部件，因此不能承诺文件级无损。只验证了一份合成文档；没有完成 WPS/Word 外部对照，本机也缺少 LibreOffice 独立渲染环境。Finder 自动定位未取得预期选区，鼠标拖选路径已通过。

资源实测：新装依赖约 **80.95 MiB**；下载缓存约 **46.62 MiB**；多次测试后的独立运行缓存约 **94.42 MiB**。这些不包含复用的 Electron/DSH，不是正式安装包增量。单次样本打开约 **1.14 秒**，导出约 **0.58–0.74 秒**。独立 Electron 进程工作集快照相加约 **949 MiB**，其中编辑器渲染进程约 **429 MiB**；共享内存可能重复计数，不能当作正式宿主的新增内存或聚合峰值。
