# JEV 式全局增强

此包独立维护配置、后端契约、内网传输、执行快照、运行轨迹和设置界面。它由工作台 capabilities 聚合入口挂载，前端控件由 plain-chat 的顶部栏与设置槽位挂载。岗位不需要额外绑定组件，也不获得新权限。

默认关闭。开启后使用单独选择的工作台内网模型账号；不会使用 Jev 官网 KEY。当前支持 Chat Completions 协议。凭据通过现有工作台 credentials 服务解析，仅在调用时使用。实际连接时解析并固定私网 IP，拒绝公网、混合 DNS 结果与 HTTP 重定向。IPv4 支持回环、10/8、172.16/12、192.168/16，IPv6 支持回环和 ULA。不会继承代理或切换公网兜底服务。

## 配置与作用范围

- `$DSH_HOME/jev-mode/config.json`：整个工作台共用的开关、模型和检查限额；独立 revision 防止旧页面覆盖新设置。
- `$DSH_HOME/jev-mode/traces.json`：最近 200 项摘要记录，设置页显示最近 60 项；包含本轮配置、判断依据摘要、状态和耗时，不保存完整模型思维过程。
- 每轮开始时复制并冻结配置。切换岗位、新建会话或继续历史会话时，新轮次使用当前全局设置；进行中的轮次继续使用原快照。
- 关闭时不调用决策模型。打开但配置缺失、超时、格式异常或预算耗尽时，阻止依赖检查的自动步骤；手动整理、权限、草稿发布、已有结果沿用业务模块规则。

## 执行适配

`host/native.ts` 使用宿主公开的 pre-step、pre-execute、turn-stopping 事件。普通聊天和通用岗位先评估、工具执行前检查、结束时复核。已有权限拒绝始终保留。结果需要确认时最多追加一次澄清答复，并阻止该补充阶段再次调用工具。流式答复在结束复核前可能已经可见，应以复核记录为准。

需求分析在生成前评估、采用候选结果前复核；开发助手在每轮开始评估、文件写入前检查、结束前复核；会议纪要在转写内容整理前评估、保存新纪要前复核。复核失败不会自动撤销已经完成的写入，也不会覆盖先前会议纪要。模型评估不代替实际测试结果或用户确认。

`JevBackend` 是后续扩展接口。官方后端标识 `official-reserved` 仅保留契约，当前不可用，不包含官方客户端或请求地址。模型输出的判断属于语义审查，不是官方 Jev 的校准概率。

## 开发与回归

修改核心或 UI 后，需要同时构建 `dsh-jev-mode`、`dsh-capabilities` 和 `dsh-client-ui-plain-chat`：后两者在构建时合入本包对应源码。SDK 由运行中的工作台提供，验收必须使用与宿主相同的一套类型，避免混用不同安装树中的品牌类型。

包内测试覆盖设置持久化、并发保存、取消/限额、内网传输、宿主路由认证和原生 Agent 事件。业务适配回归在 `dsh-capabilities/tests/jev-adapters.spec.ts`；岗位切换与新对话继承在 plain-chat 的 `tests/ui.spec.tsx`。

发布前保留代码基线与实际运行包备份。回退运行包必须与源码版本对应；独立的 JEV 配置和原有业务数据都保留，回退不是删除历史数据。
