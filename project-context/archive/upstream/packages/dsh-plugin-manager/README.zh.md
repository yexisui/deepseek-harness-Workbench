# @linxin666/dsh-client-ui-plugin-manager

[English](README.md) | 中文

DSH 插件设置中的插件管理器：安装、启停和卸载插件，检查安装冲突并创建修复会话。插件版本检查与更新操作已禁用。

## 能力

- 注册插件管理标签页，并提供共享的 pluginManager 服务。
- 保留 npm、Git 和本地包安装。存在官方安装器 RPC 时使用该通道，否则使用本机 HTTP 网关和官方 DSH CLI。
- 列出已安装插件及聚合包子插件，提供下次启动生效的开关；管理器必需的入口保持启用。
- 显示安装进度、冲突提示、启动失败和修复会话。需要重启的变更在用户重启宿主后生效。
- 不发起注册表版本检查或遥测请求。旧 update 和 check-updates HTTP 接口返回 410，对应服务方法直接拒绝，不调用官方 RPC 或 CLI。

## 安装

使用工作台部署流程或现有插件安装流程。npm、Git 和本地安装保留原行为，包括依赖下载和包脚本。离线部署所需依赖仍由部署者提前准备。

## 配置

此标签页没有配置命名空间。插件启停状态持久化后在下次启动生效。存在官方安装器通道的运行环境使用该通道管理本机插件，否则由网关通过官方 CLI 和原子补丁写入管理 profile。

## Cordis 服务

浏览器提供 pluginManager，包含 isLoopback、list、install、uninstall、status、failures、setEnabled 和 onChange。标签页与其他消费者共享同一接口，成功变更后通知监听者。用于兼容的 update 和 checkUpdates 方法立即拒绝。

## 已知限制

- 插件管理仅限本机。远程浏览器显示本机操作提示，远程 HTTP 请求被拒绝。
- 安装可能需要网络。本地导入插件不代表其全部依赖已可离线使用。
- npm Web 运行环境没有启动失败环或安全模式，安装错误仍可交给修复会话。
- CLI 预检检查组合和无法解析的入口引用；运行时导入或 apply 错误仍可能在下次实际启动出现。
- 本包不控制 Harness 基座更新，也不控制独立暴露的官方安装器功能。

## 安全模型

每个网关路由检查 socket 地址、Host、Origin 和跨站请求元数据。安装仍属于本机代码执行，包脚本保留原行为。危险 shell 字符和无效 profile 名称会被拒绝。

变更串行执行。安装必须实际新增依赖才视为成功；重复入口或无法解析的入口会回滚新包。重复挂载保护只移除新引入的冲突 bundle 项。启停操作重新检查归属，并通过备份及原子替换写入。
