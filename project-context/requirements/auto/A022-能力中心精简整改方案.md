## 一 复杂的原因与整改目标

从截图和当前代码看，复杂主要来自信息层级与重复展示。四项能力已占据两排大卡片，每张卡片都重复显示来源、长介绍、岗位数量、收藏文字和底部管理区；首页又把状态、使用关系和回收站并列成五个栏目。进入详情后仍有五个栏目，修改说明、修改动作和修改组合又会进入同一编辑器。

这让用户在完成“找到某项能力并配置”之前，需要先理解许多管理概念。整改应优先减少常驻信息和入口，而不是先增加更多分组、更多视图或新的中心。

| 已核实的问题 | 对用户的影响 | 建议的处理 |
| --- | --- | --- |
| 全部、收藏、待就绪、未使用、回收站五项并列 | 收藏、状态、使用关系和生命周期被当成同类选项 | 常驻全部与收藏，状态和使用关系进入筛选，回收站独立进入 |
| 图钉、卡片描边与已收藏文字重复表达收藏 | 每张卡片有多处视觉强调 | 保留已确认的深色图钉；移除已收藏文字和额外收藏描边 |
| 所有卡片反复展示内置能力及岗位数量 | 次要信息比名称和状态更抢眼 | 来源进入详情；岗位关系在使用情况中集中查看 |
| 管理能力按钮为每张卡片单独占一整行 | 列表变成大块展示区，浏览成本高 | 名称和主体成为详情入口，保留箭头提示；移除独立按钮底栏 |
| 能力中心顶部与设置侧栏同时提供组件中心 | 相同目的地重复占据主要位置 | 移除首页顶部重复按钮；保留设置侧栏和组件编辑时的上下文入口 |
| 概览、说明、默认配置相互跳转 | 调一次配置需要理解多个栏目 | 合并为设置，并复用原有配置表单 |
| 浏览器默认配置显示动作，其他能力默认配置显示服务表单 | 相同栏目名字含义不同 | 服务配置归设置；动作和组件归组件 |
| 首页末尾长期显示会议录音专属说明 | 全局列表夹杂某个能力的业务提示 | 移至会议设置及录音上传前，相关信息在真正需要时出现 |

整改目标是让用户扫一眼知道“有哪些能力、目前是什么状态”，打开后知道“下一步在哪里操作”。不在本轮引入新的工作流编排、能力市场、批量操作中心或卡片与列表双视图。

## 二 首页采用紧凑能力列表

建议采用单列紧凑行。当前设置弹窗的内容区不宽，单列更适合横向放置名称和状态，也能为后续增加能力预留空间。

```text
能力中心                                  ＋ 创建能力   更多

搜索能力名称或用途…
全部    收藏                                  筛选

图标  浏览器操作                  待连接        图钉   ›
      打开网页、读取内容与截图

图标  会议录音转写                待配置        图钉   ›
      上传录音并转写为文字

图标  需求分析                    可使用        图钉   ›
      澄清目标并整理需求

图标  开发工作区                  项目内检测    图钉   ›
      查看项目、Git 变更与检查结果
```

这是首页结构示意。每行约 76–88 像素作为实施起点，名称一行、说明最多一行；具体尺寸以设置内容区和缩放实测为准。状态保持真实语义，开发工作区不能因为没有浏览器连接而被标成待连接。

| 每行保留 | 调整方式 |
| --- | --- |
| 原图标与能力名称 | 保留已有图标和配色；长名称可在详情查看完整内容 |
| 一句用途说明 | 首页使用简短摘要；完整介绍保留并参与搜索，不直接截断存储数据 |
| 一个主要状态 | 状态由共享描述与适配器提供；详情展示具体原因和检查依据 |
| 收藏图钉 | 沿用深色实底白图标及收藏名称；失败时回滚显示 |
| 详情入口 | 点击名称或主体进入设置；图钉独立操作，不触发跳转 |

移除能力的垃圾桶移到详情标题右侧，带提示和可访问名称。用户从首页进入详情后即可找到；不把移除伪装成普通开关，也不删除现有影响确认。与之不同，组合编辑器内的组件移除仍保留每行右侧垃圾桶。

首页没有用户自定义顺序的新增需求，继续沿用现有收藏优先的稳定顺序。若以后增加排序，必须遵守整框拖动规范，不出现上下箭头或只允许拖动小手柄。

创建能力保留为标题区的次级按钮，不再与正常使用争夺大面积主按钮。更多菜单首版只放回收站，不为了填满菜单加入导入、批量管理等新功能。回收站非空时可在菜单项显示数量。

## 三 把五个列表栏目整理为两个栏目和筛选

| 现在 | 调整后 | 具体行为 |
| --- | --- | --- |
| 全部 | 保留 | 默认展示所有未移除能力，保留搜索和收藏优先 |
| 收藏 | 保留 | 仅查看收藏能力，使用现有收藏数据 |
| 待就绪 | 放入筛选 | 状态筛选：需要配置或连接、草稿、已停用；检查中和未知单独说明 |
| 未使用 | 放入筛选 | 改名为未关联岗位，明确与执行历史不同 |
| 回收站 | 更多菜单内进入 | 打开独立回收站视图，沿用恢复、批量选择和永久删除保护 |

筛选弹层只保留两组：状态、岗位关联。不同组之间取交集；同组允许多选时取并集。搜索、全部或收藏和筛选共同生效。存在筛选时显示已选条件与清除入口，避免用户误以为能力丢失。

未关联岗位的基础口径沿用现有草稿或最新岗位版本引用。它不表示历史上从未使用，也不能作为永久删除依据。回收站的删除保护继续检查更完整的历史引用，不能因为列表显示零关联就允许删除。

返回能力列表时恢复查询、栏目、筛选和滚动位置。回收站使用单独的查询状态，离开后恢复原列表条件。旧页面定位请求通过兼容映射进入新位置，不反复重放。

## 四 能力详情五个栏目合并为三个

推荐设置、组件、使用情况三个栏目。全部合成一张长表会让服务设置、组合草稿与岗位引用难以区分，三个栏目可以在精简后保留清楚的操作边界。

| 原栏目或内容 | 新位置 | 合并后的行为 |
| --- | --- | --- |
| 概览与连接 | 设置顶部 | 状态、原因、启用状态和当前必要的下一步放在一起 |
| 默认配置中的服务表单 | 设置主体 | 复用已有语音识别、需求、项目配置表单及唯一数据源 |
| 使用说明 | 设置下的折叠区 | 默认显示一句用途，展开阅读完整说明；编辑进入现有能力编辑器 |
| 浏览器默认配置中的动作 | 组件 | 与所选组件和动作放在同处，避免两处展示与编辑同一内容 |
| 关联组件 | 组件 | 紧凑组合摘要，点击编辑组合打开现有三栏编辑器 |
| 使用岗位 | 使用情况 | 当前关联岗位列表，标明草稿或具体发布版本，支持回到原岗位编辑 |
| 版本、稳定 ID、来源与依赖细节 | 相应栏目内的折叠区 | 初始全部收起；不增加常驻版本页签 |

### 设置的默认展开内容

上方显示能力名称、简短介绍和真实状态，右侧保留编辑能力与移除图标。下面显示最相关的设置项；使用说明和技术信息默认折叠。

- 浏览器：保留启动本地连接、检测连接的真实操作。未连接时突出启动连接；已有结果时突出检测连接，其他操作降为次级入口。没有实现的填写、提交或白名单功能继续说明限制。
- 会议录音转写：复用语音识别设置；已填写配置只能显示已配置，不能宣称连接验证或转写成功。录音发送目的地说明放在此处，并在上传前可见。
- 需求分析：复用现有模型与默认配置，显示当前配置状态；任务成功与配置状态分别展示。
- 开发工作区：复用项目相关设置；明确实际检查在绑定项目的任务中完成，保持默认只读及现有权限。

### 组件与编辑器

保留左侧组件库、中间当前组合、右侧信息与配置的共享编辑器。普通用户在详情只看到当前组件摘要；需要改组件时才进入完整编辑界面。组件缺失时显示明确原因和补回入口，不折叠掉阻断信息。

使用说明编辑和组合编辑继续复用同一能力草稿。打开时定位相应区域；保存草稿与检查并发布保持两个含义明确的操作。服务配置有自身的保存、取消和作用范围提示，不被能力草稿的保存按钮顺带提交。

### 使用情况

默认展示当前关联岗位。历史版本引用如需展示，按需展开并使用既有可靠查询；不能为精简界面新造一个不完整的引用计数。详情没有岗位时显示暂无关联岗位，并提供已有岗位管理入口，不新增自动分配或批量采用行为。

## 五 可以合并的入口与应保留的业务边界

| 对象 | 本轮推荐 | 原因 |
| --- | --- | --- |
| 能力中心首页与管理能力按钮 | 合并为点击能力行打开详情 | 每项能力只保留一个主要查看入口 |
| 概览、说明、默认配置 | 合并为设置 | 都在回答如何配置及如何使用此能力 |
| 浏览器动作设置与关联组件 | 合并到组件 | 动作属于具体组件组合，不需要独立重复入口 |
| 能力中心顶部组件中心按钮 | 移除重复入口 | 设置侧栏已经有组件中心，组合编辑器保留上下文入口 |
| 能力中心与组件中心 | 本轮保留各自页面 | 能力是供岗位使用的组合，组件中心管理共享组件及来源，两者修改范围不同 |
| 组件中心与插件 | 继续分别管理，复用真实关系跳转 | 组件不等于安装包，同一插件可能提供多个组件或仅作为运行支持 |
| 能力草稿保存与服务配置保存 | 各自明确保存 | 一个生成能力定义，一个影响共享服务配置，不能因为同页就绑定提交 |
| 保存草稿与发布 | 保留两个操作 | 未完成的草稿应能保存，发布仍须通过后端校验 |
| 停用、移入回收站、永久删除 | 保留不同语义 | 涉及不同的引用、历史记录及执行影响 |

如果完成本轮后仍认为整个设置侧栏过长，可另行评估把组件中心放进能力中心的高级管理入口。这会改变此前确认的一级导航，需要单独审阅。现在先收掉重复入口，不同时重排插件、Agent 预设、岗位助手与其他设置。

## 六 状态展示统一且保留真实性

当前卡片已有共享状态函数，但待就绪筛选仍在页面内单独判断，还按特定能力 ID 分支。整改应让列表、筛选、详情和岗位编辑器共同读取相同的状态结果，避免卡片说一种状态，筛选却按另一套逻辑归类。

| 状态维度 | 首页如何表现 | 详情如何说明 |
| --- | --- | --- |
| 生命周期 | 草稿、已停用；已移除只在回收站出现 | 当前发布版本、恢复与启用规则 |
| 组件完整性 | 组件缺失或组件已停用 | 具体组件、受影响动作和补回入口 |
| 服务配置 | 待配置或已配置 | 缺失项及真实配置入口，明确影响范围 |
| 连接检查 | 待连接、连接异常或当前检测结果 | 检查时间、结果和可执行的检测操作 |
| 运行环境 | 项目内检测 | 需进入哪个任务或项目才能确认 |
| 数据读取 | 检测中、状态未知 | 读取失败原因及重试入口，不能当作零引用或可用 |
| 任务结果 | 首页不汇总成健康状态 | 在对应任务中查看是否执行成功 |

首页一个主要状态应按明确规则选择：先体现移除或停用，其次未发布，再体现组件阻断，最后是配置、连接或项目检查结果。被覆盖的其他事实在详情保留。若有关状态读取失败，展示未知和原因，不能把暂时没有数据直接判定为待配置。

已发布版本的就绪结果与未发布草稿分别处理。若草稿名称、说明或组合与发布版本不同，界面必须能识别有未发布修改；不能用草稿展示内容搭配发布版状态却不作区分。此项作为实施回归重点，不在本轮只读分析中宣称全部路径已存在缺陷。

## 七 统一实现与配置保护

### 复用已有实现

正式设置入口目前注册的是 ManagedCenter。仓库中仍有旧 CapabilityCenter 预览实现，不能只修改这个名字相似的旧页面，造成方案已写但正式界面没有变化。

| 实施位置 | 预期改动 |
| --- | --- |
| ManagedCenter.tsx | 首页布局、栏目映射、详情共享外壳和导航恢复；减少按能力名称写死的页面分支 |
| ManagedCapabilityCards.tsx 及共享样式 | 抽出紧凑能力行；回收站保持自己的选择与操作能力，避免误受首页样式影响 |
| capability-presentation.ts 及状态适配层 | 提供统一展示状态与筛选分类；保留配置、连接和执行的区别 |
| ComponentComposition.tsx 与 ManagedWorkbench.tsx | 复用现有组合编辑，不复制新的轻量编辑器；保护缺失草稿、补回和整框拖动行为 |
| 服务设置组件 | 原表单与保存接口复用，只调整承载位置；不增加第二份凭据或默认配置 |
| workbench-navigation.ts 及相关入口 | 映射旧栏目、保留来源快照、草稿和滚动，复用已修复的返回保护 |

### 旧入口与兼容

旧 overview、instructions、defaults 定位到设置中的相应区块；浏览器动作类 defaults 定位到组件动作摘要。旧 components 定位到组件，旧 roles 定位到使用情况。兼容映射必须依据能力适配描述，而不是全局把所有 defaults 链接机械替换成同一位置。

旧栏目记忆通过读取兼容转换，不批量改写能力数据。未识别的栏目安全回到设置并保留当前对象。组件、插件和岗位往返恢复原来源；关闭最上层编辑界面时不得同时关闭底层岗位草稿。

### 数据与权限

本轮优先做展示、入口和共享状态整理，不要求迁移业务记录。保持能力与组件 ID、收藏值、启停状态、草稿、发布版本、岗位绑定、历史会话和服务凭据。

必需组件可以从草稿移除并恢复；缺失草稿可保存但不能发布。发布与执行继续由后端校验。会议、需求和开发的专用路由边界不变，组件能被展示或拖入不等于已经支持跨流程执行。

正式实施前记录代码基线，必要时备份实际运行包和受保护配置摘要。分阶段独立提交，保留可回退路径；不得因界面整理覆盖其他正在进行的工作。

## 八 分阶段实施和交付

| 阶段 | 内容 | 交付门槛 |

### 14.1 两端流程

### 15.2 制作规范与真实支持范围

本轮实现 `dsh-worker-v1` 协议：一个能力包内含明确声明的 CommonJS 执行组件，每个组件导出 `execute`；依赖由制作者在外部打包，资源和说明必须列入清单。工作台不会执行开发目录的构建或依赖安装脚本。包限制为 500 个交付文件、64 MiB，校验 SHA-256、相对路径、唯一文件名和已支持协议。

- [能力制作与分发说明](../../../deepseek_harness_desktop/packages/dsh-capabilities/DISTRIBUTION.md)

这是受信任的本机 Node.js 代码协议，Worker **不构成安全沙箱**。导入确认展示本机文件/网络访问能力；确认后检查模块可加载且提供 execute，此时会运行模块顶层初始化代码，但不调用业务动作。声明动作和岗位授权约束工作台调用路由，不能隔离恶意本机代码。停止/超时终止 Worker 及工作台代理模型调用，无法撤销已发生的外部副作用；开发者不得启动脱离调用生命周期的进程。

新能力可随包提供全新的执行组件，导入后不需要重启即可按调用加载。完整 Cordis 插件、浏览器扩展、驱动等由原真实管理入口处理，不能当作本协议包直接装入；未知协议会明确拒绝。内置会议、需求、开发等专属工作区随应用交付，不提供虚假的独立导出；导出列表只展示有完整代码包的版本。导入组件不建立虚构插件项，组件关系指向真实的能力运行适配器。

模型调用复用工作台既有账户，包里只声明是否需要模型，本机模型选择与密钥不进入导出。导入就绪表示文件、适配器和所需配置可用；连接及任务成功以实际调用为准。一次调用最多 180 秒，全局最多并行 4 个；停止、停用、岗位撤权、回收站移除均校验真实授权。既有岗位固定版本继续调用对应旧代码，导入本身不会修改岗位授权或自动执行任务。
