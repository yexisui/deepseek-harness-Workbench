## 用户需求及实现

顶部岗位入口旁增加 JEV 开关及设置按钮。JEV 是独立全局附加功能，切换岗位、新对话、继续历史会话和重启沿用同一开关与决策模型。岗位模型、岗位权限、既有选择联动和草稿保持。首次默认关闭，决策模型需在 JEV 设置中单独选择并保存。每轮开始固定配置快照，中途切换从下一轮生效。

独立源码包：deepseek_harness_desktop/packages/dsh-jev-mode。包含配置、后端接口、内网传输、原生 Agent 适配、轨迹和前端设置；通过 capabilities 与 plain-chat 的现有挂载入口接入，构建时分别合入宿主与客户端。无需为每个岗位绑定组件。组件中心提供同一 JEV 设置及轨迹入口。它是全局运行增强，不作为岗位可拖入、发布或回收的业务组件；实际开关、保存、取消、状态、返回和未保存离开保护复用现有管理流程。

默认使用工作台已有账号的内网 Chat Completions 模型。设置页仅读取本地已配置的模型，不触发在线模型发现。支持 HTTP(S)、现有 Bearer 凭据引用；自定义鉴权头或其他模型协议暂未适配。实际连接校验并固定私网地址，拒绝公网地址、含公网结果的 DNS 和重定向；不使用代理或公网兜底。没有 Jev 官网 KEY、官方 SDK 或官方请求地址。官方后端通过 JevBackend 契约及 official-reserved 标识保留，当前不可用。

执行为“任务评估 → 关键动作检查 → 结果复核”：通用岗位/自由聊天通过公开 Agent 事件；需求分析复核后采用候选；开发助手写入前审查，并再次检查真实岗位权限和文件版本；会议纪要通过复核后保存新结果。关闭时不调用决策模型。缺失配置、错误、超时、预算耗尽会阻止依赖检查的自动步骤，不会偷偷降级成已通过。检查不代替权限或测试；已有拒绝优先。原生流式文字可能先于结束复核显示；复核需要澄清时会补充说明，已执行写入不自动撤销。

独立数据位于 DSH_HOME/jev-mode/config.json 与 traces.json。开关、模型、限额有修订号并持久化；旧页面保存冲突会被拒绝。轨迹最多保留 200 项、界面显示最近 60 项，记录依据摘要、状态、耗时及当轮配置，不保存完整模型思维过程或账号凭据。JEV 式语义审查不等同于官方 Jev 的模型能力或校准概率。

## 正常使用

正常关闭并重新启动工作台后，顶部岗位入口旁出现 JEV 开关。打开其设置，选择或填写“提供方/模型标识”，在关闭状态执行“检查内网模型”，通过后开启并保存配置，再发起新一轮任务。切换岗位无需再次绑定；关闭只影响之后新开始的轮次。正在执行的轮次需要立即停止时沿用原停止按钮。

首轮诊断脚本把普通回答也限制为2000 token，模型将该额度用于思考后返回 length，未产出正文；这是测试脚本参数问题，不能计为完整链路成功。调整为低思考强度，普通回答上限8192、审查仍2000后，5次请求均返回200/stop，四条JEV轨迹符合预期。两轮合计7次请求、11718 tokens；仅保存回答、判断摘要、HTTP状态、用量和耗时，未保存隐藏思维。
