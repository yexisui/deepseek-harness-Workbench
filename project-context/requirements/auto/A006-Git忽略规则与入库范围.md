## 仓库范围

以工作台根目录作为未来 Git 仓库根目录，使 deploy.ps1、一键部署.cmd 及源码子目录位于同一个仓库。用户后续明确要求需求文档、事项台账和 AI 协作配置仅保留在本机，不纳入 Git。新增的根 .gitignore 与源码已有的下级 .gitignore 共同生效。

## 排除内容及依据

| 范围 | 原因 |
| --- | --- |
| 根 runtime-node、runtime、runtime-desktop、runtime-dev | deploy.ps1 可重建；开发环境中的缓存、构建镜像、日志和备份一起留在本地 |
| 根 dsh-data、chat-data、desktop-state | 本机模型配置、凭据、会话、插件安装数据、聊天目录及桌面状态 |
| 根 qa-chat | 隔离验证环境 |
| 各层 node_modules、工具缓存、测试输出、运行日志 | 可生成的依赖和临时产物 |
| .env、.env.*、.npmrc、.dev.vars 及变体 | 本机环境变量和认证配置；显式保留 example、sample、template 模板 |

根环境规则使用前导斜杠，避免误伤源码内部同名目录。源码中的 desktop/runtime 是打包依赖清单及锁文件，必须保留；desktop/build 是安装器源码，也保留。

不全局忽略 lib、dist、build 或压缩包。原项目明确要求提交四个包的 lib 及 market/dist；现有下级规则继续排除其他指定构建目录、desktop/resources/runtime 和桌面安装包输出。package.json、package-lock.json、pnpm-lock.yaml、部署和启动脚本继续入库。需求文档及附件、事项台账和 AI 协作配置按用户后续要求排除。

部署脚本内嵌公开依赖清单与锁文件基线，因此根运行环境里的 package.json 和锁文件无需额外提交。新机器仍需联网部署并重新配置模型，私人数据不会由 Git 恢复。首次联网完整部署和模型回复的历史待验证状态不因本次忽略规则核查而改变。
