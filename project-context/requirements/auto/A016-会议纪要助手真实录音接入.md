## 产品流程

保留现有工作台会话栏、岗位卡片、对话/轨迹页签和底部输入框。进入会议纪要助手后先选“快速生成”或“引导整理”：前者上传录音后自动转写并生成纪要；后者先选用途和重点，上传后核对说话人与转写文字，再生成。转写结果如有时间戳可跳转回听。纪要可继续对话修改、复制，或通过系统打印窗口保存 PDF。会话重开通过本地任务 ID 读取结果；删除本地会话时删除相应录音和任务。

## 模型接入与配置

识别服务使用通用的 OpenAI 兼容音频转写接口：向配置的完整接口地址发送 `multipart/form-data`，字段包括 `model`、`response_format`、`file`；支持返回 `segments`（`start/end` 以秒计，可带 `speaker`）或只有 `text` 的 JSON。若只返回全文，界面仍可核对文字，但没有逐句时间戳和说话人信息。当前实现不要求供应商是阿里云，可接云端或本机兼容服务；其他协议需另加适配器。

启动桌面服务的环境变量：

| 变量 | 作用 |
| --- | --- |
| `MEETING_ASR_URL` | 必填，兼容接口完整地址，例如以 `/audio/transcriptions` 结尾；远程须 HTTPS，本机 localhost 可 HTTP |
| `MEETING_ASR_MODEL` | 必填，识别服务接受的模型标识 |
| `MEETING_ASR_API_KEY` | 可选，按 `Bearer` 发送；本机无需鉴权的服务可以不填 |
| `MEETING_ASR_RESPONSE_FORMAT` | 可选，默认 `verbose_json`，也可填 `json` |
| `MEETING_ASR_MAX_MB` | 可选，默认 25 MB，服务端上限 100 MB；还须符合识别服务自身限制 |

纪要生成直接调用工作台 `llm` 服务。对话中的“纪要模型”下拉框读取工作台已有模型列表，默认跟随工作台默认模型；上传前可选定，也可在纪要生成后换模型重新生成。模型账户与密钥沿用工作台原有配置。识别服务的 API Key 仅从服务端环境读取，不发送到浏览器或存入能力卡片。配置环境变量后由用户正常重启桌面服务。能力中心展示识别接口配置状态；该状态只检查配置存在，不表示凭据或接口已实际验证。

录音及结构化任务数据存于 `dshHome()/capabilities/meetings`。主机接口继续使用现有本机来源限制和工作台连接鉴权。后台异步处理，前端轮询显示进度；工作台重启造成的未完成任务会标为失败，可重试或重新上传。

- 浏览器操作使用共享组件列表和三栏组合编辑器，支持组件移除确认、缺失依赖草稿、补回、拖拽排序、保存与发布。会议能力在 ManagedCenter.tsx 的 ComponentRelations 中提前返回一张静态说明卡，因此没有这些入口。

- 会议组件在前端被标为不可移除，后端 capability.save 对草稿和发布均要求保留唯一转写组件及动作；现有复制和其他能力/岗位引用限制也绑定会议专属标识。因此不能只加垃圾桶而不改校验。
- 会议服务读取已发布能力和岗位状态；转写接口配置已可在“默认配置”中编辑、保存。纪要使用工作台 llm 服务，在对话中选模型。组件描述中的 /meeting 并非当前包独立导出的插件入口，不能机械复用浏览器的“查看组件”跳转。
