## 结论

可行性高，推荐“Everything 提供本机文件索引，工作台提供统一能力、岗位和搜索 UI”。首版优先使用官方 ES 命令行调用适配，必要时再改为 SDK/IPC。将 Everything 原生窗口嵌入 Electron 不利于现有主题、布局、焦点和统一组件复用，不作为推荐方案。自行遍历全盘重建同等级搜索引擎工作量明显更大。

首版按文件名、路径、扩展名、修改时间查找，显示文件/文件夹及元信息，提供打开所在位置和复制路径。完整正文检索、语义检索以及让模型阅读 Word/PDF 等属于后续独立范围，不能把快速文件名搜索等同于全文知识库。

## 集成方式比较

| 方式 | 评价 |
| --- | --- |
| 官方 Everything + ES.exe | 首选验证路径。可被 Node 宿主作为隐藏子进程调用，支持结构化输出、筛选、限量和排序。锁定 Everything/ES 配套版本后验证中文、空格、分页与参数转义 |
| 官方 SDK/IPC | 可行。适合后续更密集的交互查询；仍要求 Everything 客户端进程运行，需要原生桥接或小型独立适配程序 |
| Everything HTTP | 可用作其他场景的方案，但当前本机桌面集成没有必要新增监听服务和配置面 |
| 自建文件索引 | 可跨平台扩展，但扫描、监听、索引修复等维护范围较大，当前需求不建议首选 |

建议调用链：宠物/搜索页面/明确的查找指令 → 工作台搜索服务 → ES → Everything 客户端与索引 → 限量元数据结果。

注意：Everything Windows Service 与 Everything 客户端不是同一角色。仅安装服务或仅放置 SDK/ES 文件不足以查询；客户端也需要运行，可后台驻留。NTFS 快速索引可借助 Everything 服务使客户端保持普通用户权限。首次服务安装可能触发系统提权，不能通过把整个工作台长期提升为管理员来替代合理安装。

官方当前下载页面区分 1.4.1.1032 普通版与 1.5 Beta；本方案不依赖 Beta 专属功能。Lite 版缺少 IPC，不能用于 ES/SDK 接入。官方网页存在版本混合的选项说明，具体 ES 开关和 JSON/CSV 编码以最终锁定版本实测为准。

## 需要明确的边界

- “全部本地文件”应表述为“全部已索引的本地位置”。NTFS 最适合快速索引；FAT/exFAT、外置盘、网络位置需要相应目录索引且刷新机制不同，离线盘和未索引位置不能保证实时覆盖。浏览器连接远程工作台时搜索的是宿主机器，不是浏览器所在电脑。
- 文件搜索产生的是外部文件引用。录音删除路径会删除其专属录音目录，绝不能照搬到搜索结果：删除搜索记录只删记录，不删、移动或改名原文件。
- 搜索状态区分工具缺失、客户端未运行、索引加载中、查询失败、无匹配和已就绪。未加载不能作为“0 个文件”吞掉。ES 的数据库等待选项不能替代宿主的总执行超时与取消。
- 实现采用参数数组启动受控可执行程序，禁止将搜索文本拼为 shell 命令；同时防止用户关键词被解释成 ES 管理/导出选项。限制单次结果、支持取消及旧请求丢弃，避免逐字创建无上限子进程。
- 本机搜索默认只返回必要元信息；读取文件时检查当前文件存在、访问权限、目标位置和岗位范围。面向远程客户端复用现有认证，不能无鉴权暴露整盘文件名；直接打开 exe/脚本不作为首版默认动作。
- 查询历史和索引数据库留本机，不进入 Git/能力包。公共工具二进制不入源码，放 external-tools/everything；用户已有实例应检查后复用或独立管理，不能覆盖已有索引配置。
