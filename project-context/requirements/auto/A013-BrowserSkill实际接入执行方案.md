## 1. 接入对象与管理定位

首个实际接入对象建议选择 Tencent/BrowserSkill，能力中心显示“浏览器操作”，技术信息显示 BrowserSkill、来源及版本。此前 Documents、Sheets、Knowledge、Files、Mail 是 UI 示例能力名称，尚未对应选定、安装并验证的技能包；不能把这些卡片当成已经可用的 Skills。

BrowserSkill 的 DSH 专用插件为 `@wxg-prc-cpg/browser-skill-dsh-plugin`，内含 `browser-skill` 技能说明，通过六个结构化 browser_* 工具调用 bsk CLI，由本机 daemon 与 Chrome/Edge 扩展完成浏览器操作。DSH 接入无需另行运行通用的 bsk install-skill；不应把通用 CLI Skill 的命令说明混入 DSH 专用技能。

职责建议：
- 插件管理：安装包、版本、依赖、启停与代码回退。
- 能力中心：连接状态、使用说明、默认配置、岗位引用与连接诊断。
- 岗位助手：选择能力、保存岗位专属设置，并把这些设置传给实际会话。
- 会话页面：查看浏览器工作状态、暂停/停止操作与人工接管提示。

保持一份安装记录与稳定能力 ID；能力中心引用插件记录，不再建立第二套安装器。

## 2. 本轮核实的事实

- 工作台当前 HEAD 为 ab21dbc，包含能力中心与紧凑配件列表 UI。capability-preview.tsx 明确使用内存状态，没有持久化或调用宿主 API。
- ChatStart 创建会话时固定传入 workbench-chat；其 no-tools.mjs 同时使用 tools.restrict({ allow: [] }) 和 tools.guard 拒绝工具调用。当前岗位选择不能实际授予浏览器能力。
- 本地 SDK 类型提供技能注册、Agent 作用域及工具执行 guard；具备扩展入口。但工具 restrict 仅过滤全局工具，作用域内注册仍需执行 guard 覆盖，不能只靠界面隐藏或工具目录过滤。
- 当前离线插件导入已支持构建后的 JS、dsh.bundle.patch、client 导出与共享依赖检查；不下载缺失依赖、不运行安装脚本。BrowserSkill 包的声明结构与此方向相符，仍须实包预检和加载验证。
- 本地相关 SDK 为 0.1.5-rc.1；上游主分支插件清单标注 0.3.0、部分 SDK peer 范围为 ^0.1.0-rc.6。版本范围不能代替实际兼容测试；本轮没有核实 npm 可下载发布产物与主分支完全一致。
- 上游支持 Windows x64、Chrome 和 Edge；浏览器观察 UI 要求 localhost/loopback 访问。首期按本机工作台部署。
- 上游已有延迟加载技能与工具、会话清理、截图观察等能力。延迟加载不等于岗位授权；插件拥有某个浏览器会话也不自动证明不同岗位之间已隔离。

## 3. 建议实施阶段

### 阶段一：备份、版本选定与隔离验证

从当前 Git 状态核实修改边界，保留其他任务未提交改动，建立 BrowserSkill 接入前标签与单独功能分支。备份此次将变更的配置和数据；密钥、会话、浏览器数据不加入 Git。

选择可取得、可复现的插件、CLI/daemon 与扩展兼容版本组合，记录来源和校验值。在独立测试 profile 中先验证当前 SDK、技能服务、工具 schema 和客户端加载；先尝试适配当前版本，不以全局升级 SDK 为默认手段。

准备符合既有离线导入约定的构建包。bsk 运行文件建议独立置于源码外的 runtime/browserskill，运行状态建议隔离在 dsh-data/browserskill，通过明确路径配置；具体子目录以兼容验证结果为准。浏览器扩展保持独立安装/连接步骤。

交付：版本清单、离线安装包、测试 profile 加载结果与诊断结果。此阶段成功不代表模型已能完成浏览器任务。

### 阶段二：能力中心与岗位的真实数据

增加薄的本地能力管理适配层，复用现有安装服务、官方技能注册与会话预设接口；优先复用上游 BrowserSkill 执行实现，不复制整套浏览器引擎。

能力定义保存能力 ID、实现插件、版本、基础说明、自定义补充说明、默认选项。岗位保存能力引用、配置版本和显式覆盖项；共享默认值与岗位覆盖在界面中分清。默认配置变更不应无提示扩大既有岗位权限。

能力中心显示真实状态：未安装、待连接、可用、连接异常、已停用；显示实际岗位引用，支持检测连接和查看问题。编辑说明采用“上游基础说明 + 本地补充说明”，保留恢复默认和版本来源，避免升级直接覆盖个人内容。

将岗位保存、修改、重新打开、刷新恢复接通，原有拖放、紧凑卡片、面板收起等交互保留。

交付：能力与岗位配置可持久化；状态源于宿主检测，不能以勾选开关直接显示“已连接”。

### 阶段三：岗位会话调用浏览器

新对话根据选定岗位加载对应预设和能力集合。普通聊天继续维持现有工具禁用；浏览器岗位仅加载必需的技能及浏览器工具，不因此获得任意终端或文件执行权限。

授权校验放在执行层，并覆盖工具延迟注册、恢复会话、手动技能调用、作用域工具和可用的间接调用路径。绑定“岗位配置版本—DSH 会话—浏览器会话”的关系，验证不能借用其他岗位的会话 ID 操作浏览器。

首期开放指定网页导航、页面读取、截图和总结，先用测试页验证。交互、填写与提交放下一阶段。界面的“站点范围、只读、提交确认”等选项必须有真实执行约束；没有实现完整约束的选项保持禁用并说明，不把提示词当权限控制，也不宣称仅限制初始导航地址即可限制所有重定向和页面行为。

保留上游独立 Agent Window 和人工介入机制。用户已有标签页的借用遵循扩展确认设置；不同会话的归属、超时、取消、断线与资源清理需要专项验证。

交付：用户创建岗位、添加浏览器操作、保存并开启新对话，输入读取测试网页的任务，模型实际调用工具、返回网页总结，界面能显示对应浏览器状态。

### 阶段四：受控交互与正式部署

基于前述执行约束再开放点击、填写。提交与外部写入需要可审阅的确认流程；不能仅检查某个 submit 动作，因为点击按钮或按 Enter 也可能完成提交。实际实现不具备相应语义控制时，暂不承诺通用“允许填写但绝不提交”。

先在本地表单页检验行为，再验证用户选定的业务网站。复用上游观察组件并与当前会话关联，区分“停止当前命令”和“停止后续浏览器任务”，避免取消后模型立即继续操作。

正式接入前完成构建、权限及隔离测试和端到端验收；提供版本化安装包与变更说明。按用户可接受时机重启正式宿主，不在验证中强制结束正在使用的服务。

## 4. 验收和回退

验收至少覆盖：配置保存及刷新恢复、能力检测、原生工具发现、真实模型调用、普通聊天不能调用浏览器、未装配岗位不能绕过限制、不同岗位浏览器会话隔离、停用后下一次调用立即被拒绝、超时/断线/停止后资源状态正确、升级和回退。

## 6. 能力中心与插件、岗位的联动方案（2026-09-22 补充，待确认）

用户追问：既然复用了 DSH 插件，能力中心应怎样管理并体现这些关联。本节是接入方案的补充，未获正式实施授权。本轮只制作独立交互示意并更新记录，不修改工作台代码或运行配置。

### 界面与信息层级

能力中心仍以“浏览器操作”等业务能力为管理对象。列表保留名称、可用状态和岗位引用摘要；详情顶部始终显示能力启停状态、实际可用状态和岗位引用，异常原因无需进入技术信息查找。

在原有“概览与连接、使用说明、默认配置、使用岗位”基础上，增加一级页签“关联组件”。原方案中完全折叠的技术信息调整为：主要关联关系显式展示，包名、入口、详细版本等技术字段仍按需展开。

“关联组件”区分：
1. 能力实现：BrowserSkill 专用 DSH 插件，显示已安装/已加载/已停用/待重启、安装版本与运行版本，以及跳转插件管理的入口。
2. DSH 支持组件：技能注册、工具执行、会话/预设等共享服务，标明必需或可选、共享属性与实际检测状态。正常时默认折叠，异常时自动展开。最终条目以实际适配器的依赖声明和宿主探测为准，不硬编码一个固定“依赖总数”。
3. 浏览器环境：本地 CLI/daemon、浏览器扩展及选定浏览器连接，分别显示健康状态。它们属于外部运行条件，不误标为 DSH 插件。

能力详情默认展示“概览与连接”；示意图为了审阅联动设计，默认打开“关联组件”。使用说明和默认配置页保持原设计，示意只展示本轮相关视图。

### 两类状态分开

“已启用”表示用户希望该能力可被岗位使用；“可用”还要求必要插件实际加载、共享支持服务正常、浏览器环境连接成功。启用开关不能直接生成绿色“可用”。

- 接入插件未安装/已停用、必需共享组件异常：不可用，列出具体阻塞项。
- 浏览器扩展断开：待连接，保留已有岗位配置。
- 可选截图展示组件异常：可用但截图受限，不把全部浏览能力判为不可用。
- 尚未检测、状态通道断开或结果过期：待检测/状态未知，显示最后检测时间，不显示虚假的正常或零引用。
- 版本已安装但未加载：待重启，同时展示正在运行的版本，不能提前显示新版本已经生效。

### 双向定位

能力 → 插件：点击“在插件管理查看”，展开实际分组并定位对应运行条目，保留“返回浏览器操作”入口。

插件 → 能力：插件详情增加“关联能力 / 使用岗位 / 运行任务”，能反向定位能力和具体岗位配件。共享插件需要展示全部已知关联能力，而非只显示当前浏览器能力。关系尚未发现完整时标为“待核实”，不把局部数量当全局数量。

岗位 → 能力：岗位配件显示“已添加”及独立运行状态，可查看阻塞原因并跳到能力中心；返回后保留编辑草稿。依赖故障不会自动删除配件或覆盖岗位设置，允许保存待配置岗位，但运行时说明并阻止不可用能力调用。

### 操作归属与影响

- 停用能力：调整能力级调用许可，阻止所有引用岗位的后续调用；不级联停用 BrowserSkill 插件或 DSH 共享组件。存在运行任务时，先展示影响范围并提供明确停止操作。
- 启用能力：重新计算实际可用性，不暗中安装插件或启用用户已经停用的底层组件。
- 从某个岗位移除配件：只解除该岗位引用，不删除能力、不卸载插件；新会话使用新配置，已运行会话的变更范围另行明确。
- 插件安装、启停、升级和卸载：由原插件管理服务执行，能力中心提供定位入口。存在关联使用时展示受影响能力、岗位和活动任务；没有活动任务的低影响操作沿用原流程，不增加无意义确认。
- 必需插件停用或卸载后：引用关系保留，能力和岗位显示缺失/不可用，可通过恢复插件修复。卸载代码不自动删除自定义说明和岗位配置。
- 共享 DSH 组件：能力中心提供查看与诊断，维护动作集中在插件管理；不得从单个能力的停用动作级联停掉共享组件。
- 停止运行任务：立即阻止新调用，在收到执行端确认前显示“停止中”；失败显示失败原因，不能按钮一点就宣称任务已停止。

### 配置联动

能力默认设置、岗位覆盖、会话采用的配置版本分别显示。默认设置变更先列出采用默认值的岗位与有覆盖的岗位；默认不扩大已有会话的权限，明确提供应用到哪些岗位、新会话何时生效的操作。紧急停用与撤销权限通过执行层即时生效，与普通配置版本更新分开。

### 后端实现边界

建立“能力 ID → 提供插件及运行条目 ID → 必需/可选支持服务 → 外部运行条件 → 岗位引用 → 运行会话”的关系索引。一份事实记录供能力中心、插件管理和岗位编辑器读取；保留稳定身份、版本和探测时间，不按显示名称猜关联。

插件管理仍是安装信息与插件启停的来源，能力服务保存能力策略与岗位绑定，浏览器适配器报告环境状态和任务归属。优先订阅宿主状态事件，必要时有节制地轮询；修改后等待宿主确认，并处理状态通道断开、过期数据和并发更新。

### 首轮交付与验收

先交付关联组件视图、双向定位、真实状态同步和停用影响预览；复杂依赖拓扑图作为后续可选项。验证插件停用、浏览器断连、共享必需服务故障、可选展示故障、未知状态、待重启与恢复，以及岗位引用不丢失和运行中撤权。

独立示意包含六种场景、能力/插件停用影响预览、返回能力和岗位状态联动，全部数据明确为演示；不代表真实插件已经安装或运行。

### 版本核查口径补充

前文 0.1.5-rc.1 对应本地 UI 包的 SDK 开发依赖声明；后续读取工作台 runtime 下相关 SDK 包的实际 package.json 得到 0.1.5-rc.2。运行服务当前解析的完整依赖和进程已加载版本仍需在接入验证阶段核实，不将声明版本、磁盘版本或正在运行的版本混用。


## 7. 自定义能力与组件组合（2026-09-22 补充，待确认）

用户进一步提出：希望自己编辑新的能力，通过添加、移除插件组合功能。本节提出“能力构建器”，作为能力中心的新增与编辑入口。仍属方案讨论，未修改正式界面、插件、配置或后端；本节不代表此前接入工作已经启动。

### 管理对象与三个编辑层次

- 能力编辑：名称、图标、用途、技能说明、参数默认值、允许动作和组件引用，面向日常管理。
- 组件组合：选择插件已暴露并完成适配的业务功能，可添加、移除、限制动作，并保存为可复用的新能力。同一个已安装插件可被多个能力引用，不为每个能力重复安装。
- 插件开发：新增工具或修改插件自身行为，需要创建独立开发副本、修改代码、构建和测试，再经现有离线安装流程导入新版本。能力中心可提供开发入口与来源信息，首期不内置完整代码编辑器，不直接改正在加载的插件文件或 DSH 共享底座。

“从能力中移除组件”“从岗位中移除能力”“从工作台卸载插件”是三种不同操作，界面用不同名称。前两者仅修改各自引用；系统卸载仍由插件管理处理并展示全局影响。

### 入口与编辑方式

能力中心增加“新建能力”和“复制为我的能力”。内置能力保留来源与版本，自定义调整优先保存为个人副本，方便恢复和升级。

“关联组件”从只读关联视图增加“编辑组合”入口。构建器沿用已有三栏交互：左侧可用组件库、中间当前能力组合、右侧选中组件的动作和参数。主栏保留，左右可收起；紧凑卡片、拖放和落位反馈复用现有设计。

常规编辑展示已经接入的业务组件与其功能，如 BrowserSkill 提供的网页读取。显示当前来源、可用状态、可选择动作与所需运行环境。未安装的已知组件标注“需安装”，可暂存于草稿并跳转现有离线导入；未完成适配的插件不伪装成可用积木。

必需的 DSH 支持服务自动列在“运行依赖”中，提供说明、状态和定位入口；不作为可任意删除的业务积木。插件提供多个动作时允许选择已支持执行端约束的动作子集，而非一选插件就授予全部工具权限。

### 可组合的前提

关联关系可见，不等于任意插件可以自动组合。首期需要为 BrowserSkill 建立组件适配清单，至少包含稳定身份、提供插件/运行条目、可用动作、可配置参数、依赖、版本兼容性和权限边界。其他插件逐个完成适配后进入组件库。

只有界面、日志或底层服务功能的插件可以成为支持依赖，不会仅因安装成功就成为模型可调用的业务组件。也不通过包名或自然语言描述猜测它提供哪些工具。

首期支持“一个能力包含多个已适配组件，由助手依据用途和规则选择调用”。拖动排序用于管理展示，不代表后台已具备严格顺序执行。若要支持固定的读取 → 整理 → 导出流程，应另行增加流程执行、输入输出映射、错误处理与恢复机制，不能把自然语言步骤包装为已经实现的流程引擎。

### 添加、移除与权限规则

- 添加组件：检查安装与运行状态、版本兼容性、工具名称冲突及依赖；缺失时可保存草稿，满足运行条件后才能启用。
- 移除组件：只删除当前能力中的引用，展示受影响的已声明动作和参数。若仍有动作或步骤依赖它，要求同时移除相关引用或选择兼容替代项；不能仅隐藏卡片后仍让工具执行。
- 必需运行依赖由已选业务组件自动推导。依赖失效会反映到能力状态，不通过删除依赖记录消除错误。
- 多组件提供同名工具时，必须显式选择提供方或由适配层命名隔离，不能静默覆盖或让加载顺序决定。
- 组合汇总可用动作，各动作执行仍须同时满足提供方、能力和岗位限制；组合不能扩大已禁用的权限。同一工具经多条路径引用时，明确绑定来源并处理限制冲突，不能因重复引用获得更宽权限。
- 首期组合只引用基础组件，暂不支持组合能力相互嵌套，避免循环引用。之后若支持嵌套，需增加循环检测、去重与限制继承规则。

### 保存、试用和岗位联动

采用“保存草稿 → 校验 → 按需试运行 → 保存为本地可用版本”的流程。名称、说明或排列变化不强制运行真实浏览器；用户启动功能试用时，才针对选定任务实际调用工具，并显示执行记录。

已启用版本保持可用，编辑发生在草稿中。保存新版本前展示组件及权限差异、引用岗位和活动会话。岗位记录引用版本与自身覆盖值；提供明确的更新岗位操作，默认不在运行中自动切换组件或扩大权限。停用和撤销权限属于即时执行策略，不因旧版本会话仍在运行而失效。

本地保存的新能力出现在岗位助手的配件库，可像“浏览器操作”一样整体拖入。插件反向引用按“插件 → 基础/组合能力 → 岗位”追踪，避免遗漏组合带来的间接引用。同一岗位经多个能力引用同一组件时，计数区分岗位数与引用次数。

例如，在浏览器组件接入后，可以先创建“网页只读采集”，只开放已实现约束的导航、读取和截图动作。未来文档等组件接通后，才能创建包含网页读取、资料整理、文档输出的组合；当前文档、表格等示例卡片仍不视为真实组件。

### 实施优先级

1. 首先完成 BrowserSkill 接入及标准组件适配，明确“哪些动作可选、限制如何执行”。
2. 增加新建/复制能力、组件添加移除、动作选择、依赖校验和草稿保存。
3. 接通本地版本、岗位引用与影响预览，用创建两个不同动作范围的浏览器能力验证隔离；接入第二个真实组件后验证跨组件组合。
4. 根据实际需求再建设固定流程编排或插件开发编辑器。

验收包括：移除组件不卸载共享插件、必需依赖不可伪删除、未适配插件不假装可用、缺失依赖可保存但不能执行、同名工具不静默冲突、组合不扩大权限、新版本不覆盖运行中的配置、回退保留配置，以及单个安装被多个能力复用。
