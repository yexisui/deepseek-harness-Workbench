## 2. 界面与交互

- 说明改为“导入和管理本地工作台资源”。保留四类选项卡，每类显示本地可识别的资源，分类计数如保留，只代表本地数量。
- 工具栏提供“导入 ZIP”“选择文件夹”和本地搜索；搜索只筛选本地清单，不发送到外部服务。
- 资源卡片显示名称、版本、缩略图（有则显示）、来源类别、状态及对应操作。来源以“本地导入”“已有安装”等简短文字表示，不显示上游市场推广、点赞、下载量、预览网站或仓库跳转。
- 空分类显示“尚未添加资源，可导入 ZIP 或选择文件夹”。有本地资源时显示真实清单，不使用固定示例卡片。
- 已安装的芙宁娜皮肤、宠物和用户插件应被本地扫描识别，不要求重新导入。资源仍由原来的皮肤、宠物、插件、预设服务执行其功能。
- 工坊内提供适合各类资源的应用/启用/安装入口；已有独立管理页面继续保留。卸载与移除必须区分包来源及当前使用状态，不能把内置资源当作可随意删除的用户导入项。

## 3. 支持的资源格式

ZIP 与文件夹只是两种输入方式，内部内容使用项目已有资源格式。

| 分类 | 资源根目录的关键文件 | 导入后的下一步 |
| --- | --- | --- |
| 皮肤 | skin.json，以及其引用的 CSS、背景、预览图等文件 | 加入皮肤目录，用户再选择应用 |
| 宠物 | pet.json，以及图集、帧序列或受支持的模型资源 | 加入宠物目录，用户再选择启用 |
| 插件 | package.json、有效 DSH 插件声明及已构建的运行入口 | 先入本地库；用户点击安装后，通过插件管理流程接入，显示实际生效条件 |
| 预设 | preset.yml、agent.cordis.yml 及引用的随包文件 | 先进入未启用库，经检查后由用户启用 |

首版单次导入一个资源，兼容 ZIP 根目录直接放清单或只套一层资源文件夹。存在多个候选资源根时拒绝含糊导入，并提示分别选择；不自动挑选其中一个。

选中文件夹后复制所选文件形成独立资源，不依赖原文件夹的长期存在，不把用户原始目录改成运行目录。普通图片不等于完整皮肤或宠物，缺少清单时应指出缺少的文件；把任意图片转换为资源包不属于本版范围。

插件只接受可运行的发布内容或已构建目录。若仅包含需要编译的源码，应说明缺少的入口，不自动运行任意构建脚本。插件的外部依赖可能需要安装：导入和清单浏览本身不访问市场，依赖安装若需要联网，应在执行前显示对应状态，不能把所有插件承诺为完全离线可用。

## 4. 导入流程

1. 用户在分类页点击“导入 ZIP”或“选择文件夹”，选择本地文件。
2. Web 和 Electron 共用文件选择与上传入口；文件夹通过用户选择提供相对路径清单，不接受浏览器随意提交一个宿主绝对路径让服务端读取。
3. 文件进入工作台数据目录下的隔离暂存区；读取清单和文件结构，识别资源类型、名称、版本、ID、文件数量、缺失引用与兼容要求。分析阶段不加载 JS 模块、不求值预设中的内联表达式、不执行 npm 脚本。
4. 展示导入摘要；类型与当前分类不符时明确提示实际类型，避免静默错放。若存在同 ID 资源，展示现有版本及处理选项。
5. 用户确认后，宿主先完成全部校验，再通过暂存和目录切换写入正式目标；成功后刷新本地清单，失败保留旧资源并给出具体原因。
6. 导入成功只代表资源已入库，随后提供该类型的“应用”“启用”或“安装”动作。状态分别表达“已导入”“已安装”“已启用”“等待重启”等实际阶段。

导入规则建议复用既有每资源最多 2,000 个文件、单文件最多 200 MiB 的上限，并增加明确的总大小上限：首版 ZIP 上传最多 200 MiB，展开后或文件夹总大小最多 500 MiB。超限显示原因，不悄悄截断；这些数值是建议初值，可在实现时按真实样本复核。

解析需拒绝路径越界、绝对路径、符号链接/目录联接、重复或大小写冲突路径、缺失引用、压缩炸弹与不支持的加密压缩包。导入路由沿用现有本机同源门禁。服务端负责最终校验，不能只依赖前端文件选择器。

## 5. 落盘位置及 Git 范围

以下路径相对于工作台根目录：

| 用途 | 计划位置 |
| --- | --- |
| 自定义皮肤 | dsh-data/skins/<id>/ |
| 自定义宠物 | dsh-data/pets/<id>/ |
| 未启用预设库 | dsh-data/agent-presets/<id>/ |
| 已启用预设 | dsh-data/.agent-presets/<id>/，由预设管理服务控制 |
| 本地插件的持久资源库 | dsh-data/workshop/plugins/<内部资源标识>/ |
| 导入暂存、索引和覆盖前备份 | dsh-data/workshop/ 下各自的子目录 |

本地插件安装使用已验证的库内副本，经受控接口交给现有安装队列；接口传资源标识，由宿主解析实际路径，不直接接受任意命令行或本地安装字符串。安装成功要核查依赖实际落盘、bundle 注册及组合预检；后续启停/卸载复用插件管理器。

这些导入的运行资源属于 dsh-data，按当前 .gitignore 留在本机。Git 记录导入功能的源码、格式契约和部署逻辑。用户自己开发、需要版本管理的资源源文件应另放源码目录并提交，再从源文件导入；不把运行库整体重新纳入 Git。

## 6. 本地来源、脚本与启用适配

现有机制不能不加改造直接承接四类本地资源：

- 现有皮肤动态 hooks 对用户目录资源检查市场来源；有 CSS/图片不代表随包脚本自动获准执行。
- 现有预设库通过市场 provenance 判定是否托管，没有该记录的自建目录会限制管理操作。
- 现有插件管理器主要面向 npm/git，ZIP 解压本身不等于插件已安装。

因此新增独立的本地导入来源记录，记录由宿主生成的 ID、类型、版本、导入时间和文件摘要，不伪造成市场下载。预设管理和皮肤加载需要识别这类本地来源，保持原有市场资源兼容；资源包自带的同名来源记录不能直接授予信任。

纯样式/资产遵循各自已有解析和加载规则。插件、带执行内容的预设、带动态 hooks 的皮肤在执行前要有明确的安装/启用动作；界面简短说明该资源包含脚本。脚本信任绑定具体文件内容，更换版本或本地文件变动后重新确认，不能只因 ID 相同沿用旧授权。仅有本地来源记录不代表代码已经可信。

本版需完成上述适配，不能把功能验收停留在“复制文件成功”。

## 7. 重复资源、失败和移除

- 同类型同 ID 已存在：默认取消；展示版本差异并提供明确“替换现有资源”操作。替换前备份，失败恢复原资源；不能静默覆盖。
- 不自动给清单改 ID 以实现并存，因为资源可能内部引用 ID。需要并存时由资源作者提供不同 ID。
- 内置资源、官方核心插件和受保护条目不能通过本地导入覆盖。新导入插件要检查包名及 bundle 行冲突。
- 已安装或已启用的插件/预设更新和删除走原管理生命周期；不得直接删掉运行所依赖的目录。使用中的资源先走停用或切换流程。
- 对没有本地导入托管记录的旧资源先只读展示并提供原管理入口，不通过新导入器擅自接管、卸载或清空。
- 本地资源备份与 Git 代码回退分开管理。首版覆盖前备份保留在数据目录，不宣称撤销代码提交会自动恢复资源内容。

## 9. 验收范围

- 四类各以 ZIP 和文件夹进行真实导入，资源名称、文件引用、状态与后续实际使用结果相符。
- 已有芙宁娜皮肤和其他已装资源正确显示，不重复安装、不丢失原配置；普通聊天、原插件管理和 Agent 预设选择可用。
