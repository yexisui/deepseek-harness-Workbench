## 1. 推荐方案总览

采用“对话引导 + 结构化需求工作区 + 操作轨迹”的结构。保留现有岗位入口、历史会话栏、角色外观和底部输入方式；给需求分析增加能够持续编辑和保存的业务结果。

| 层级 | 建议设置 | 作用 |
| --- | --- | --- |
| 开始方式 | 快速整理、引导分析 | 分别适合已有资料、只有初步想法的情况 |
| 主选项卡 | 对话、需求工作区、轨迹 | 讨论、管理结果、查看实际操作记录 |
| 工作区子选项卡 | 概览、资料、需求清单、流程与规则、待确认、需求文档 | 六个入口围绕同一份分析数据工作 |
| 版本入口 | 放在需求文档中：当前草稿、已确认版本、版本记录 | 避免额外增加一排主选项卡 |
| 能力管理 | 沿用能力中心的五个选项卡及三栏组件编辑器 | 统一功能配置、组件关联和岗位引用 |
| 第一版成果 | 可编辑的需求条目、待确认清单、需求说明、确认快照 | 保存后重开可接着处理，并能交付讨论稿或确认版本 |

推荐第一版完成六个子页的基础行为。流程与规则先用步骤表和规则表，文档先提供 Markdown、复制和系统打印；文件解析、图形编辑及跨助手交接随后接入。

## 2. 会议纪要助手已经具备什么

本节依据正式源码静态核对和 A014/A016 实施记录，未在本轮重新运行会议任务或验证正式语音接口。

| 已核对的会议助手行为 | 需求分析可借鉴的方式 | 本次新增设计 |
| --- | --- | --- |
| 外层岗位入口、侧栏会话和原有内容容器 | 共用工作台布局和岗位外观 | 需求会话挂载专用分析视图 |
| 主选项卡为“对话 / 轨迹” | 对话内出现阶段卡片，轨迹记录步骤 | 增加“需求工作区”管理长期结果 |
| 快速生成：选择方式 → 上传录音 → 自动转写并生成纪要 | 已有资料先产生可讨论的草稿 | 资料提取后列出需求与缺项 |
| 引导整理：用途 → 重点 → 上传 → 核对转写 → 生成 | 分步提问、选项加自由输入 | 目标 → 角色与流程 → 规则 → 验收的可回访问题 |
| 纪要内容包含概览、结论、行动项、待确认 | 用稳定结构承载结果 | 需求编号、来源、确认状态、验收条件和关联问题 |
| 纪要引用转写片段，可跳转回听 | 每条结论能回到资料依据 | 来源定位到聊天消息、资料段落或会议条目 |
| 结果可复制、打印/保存 PDF、继续对话修改、换模型生成 | 共用导出和模型选择的交互方式 | 重新生成先形成修改建议，采用后更新需求草稿 |
| 后台任务保存 jobId，重开会话再读取结果 | 服务端保存结果与处理状态 | 需求数据、确认快照和恢复索引由服务端保存 |
| 会议能力有概览与连接、使用说明、默认配置、关联组件、使用岗位 | 复用统一管理导航和组件编辑 | 新增真实需求分析组件及其执行适配器 |

### 当前实现中的边界

- 会议结果已由服务端存储；客户端会话包装仍使用本地存储和历史 demo 命名。需求分析应新增清楚的数据类型，不能把需求数据塞进 meeting 字段。
- 当前本地行存储有 40 条截取逻辑。需求任务列表应有独立的服务端索引与分页，不能因会话列表限制丢失已保存的需求。
- 会议源码的轨迹主要是前端步骤文本。需求轨迹涉及确认、版本和恢复，应记录服务端实际完成的事件。
- 源码中“换模型重新生成”针对当前结果操作。需求修改应保留前后差异和人工修改，不能简单覆盖已确认内容。
- 语音服务和浏览器接管各有待验收项；需求文本分析可以独立完成，不把这些服务当作已经验证的前置条件。

## 3. 页面布局与导航

### 页面骨架

| 区域 | 显示内容 | 操作 |
| --- | --- | --- |
| 工作台左侧 | 原历史会话栏，需求分析记录使用岗位图标 | 新建、重开、重命名、通过省略号菜单移除 |
| 岗位入口 | 需求分析助手名称、现有图标与颜色 | 进入岗位配置，行为沿用当前工作台 |
| 分析标题栏 | 分析名称、保存状态、已确认数量、待确认数量 | 修改名称、选择模型、打开本次分析设置、更多 |
| 主导航 | 对话 / 需求工作区 / 轨迹 | 切换视图，保持输入、筛选和编辑草稿 |
| 主内容 | 对话消息流，或六个工作区子页，或事件列表 | 根据当前页面执行操作 |
| 底部输入框 | 文字输入、添加资料、模型入口、当前讨论对象 | 对当前需求、流程、问题或全文提出要求 |

桌面宽屏下，对话页右侧可打开紧凑结果预览；默认收起，用户点击“查看本轮结果”或某条需求时展开。需要完整编辑时进入需求工作区。这样既能边聊边核对，也有足够空间处理需求表格。

窄屏时使用全宽单栏：主导航保持可用，六个子页可横向滚动，需求详情改为全宽抽屉或独立详情区。键盘能切换页签、打开条目及返回；焦点不因后台结果刷新跳走。

### 输入框的上下文

- 对话页默认显示“讨论整个需求”。
- 在需求详情点击“围绕此项讨论”后，输入框显示“当前讨论：REQ-003 报销审批”的可移除标记。
- 在待确认页点击问题，输入框改为“回答 Q-004”。
- 用户可以移除标记恢复全局讨论。页面切换不自动把文字发送给模型。
- 在轨迹页显示“返回对话继续讨论”入口；轨迹筛选和业务输入分开，避免误发。
- 分析期间可以继续编辑输入草稿；发送按钮说明当前任务是否需要先结束，不吞掉已输入文字。

## 4. 首次进入和两条处理路线

### 欢迎页

建议文案：“描述你想解决的问题，或提供已有资料。我会帮你梳理流程、功能和待确认事项，逐步形成需求说明。”

| 入口 | 卡片说明 | 点击后 |
| --- | --- | --- |
| 快速整理 | 已有描述、纪要或初稿，先整理出需求清单 | 显示粘贴资料、添加文本文件和分析选项 |
| 引导分析 | 从一个想法开始，分步把需求讲清楚 | 先询问业务目标与当前问题 |

在未选择路线时直接输入文字，可以提交为首次业务描述，默认按引导分析接续，显示当前方式并允许切换。此行为为需求助手建议，会议助手目前要求先选方式。

### 快速整理

1. 输入分析名称，可先留空并由首段描述生成可编辑标题。
2. 粘贴描述或添加文本资料，给资料命名。
3. 选择输出用途、整理深度、重点；均有默认值。
4. 点击“开始整理”，显示实际处理阶段：读取资料、提取需求、整理问题、形成草稿。
5. 完成后消息卡显示数量，例如“发现 8 条候选需求、3 个待确认问题”；数量来自实际数据。
6. 用户查看本轮结果，选择需要采用的条目；采用进入工作草稿，确认业务需求是另一步。
7. 可以立即导出标明待确认的讨论稿，也可转入引导澄清。

### 引导分析

| 阶段 | 主要问题 | 输出 |
| --- | --- | --- |
| 目标与现状 | 想解决什么问题，当前怎么做，最影响工作的是什么 | 目标、问题、预期效果 |
| 角色与范围 | 谁使用、谁审核、哪些环节本次要做 | 角色与职责、本次包含/暂不包含 |
| 业务过程 | 从什么情况开始，先后步骤是什么 | 正常流程和初步功能 |
| 规则与异常 | 退回、撤销、权限、条件、限制如何处理 | 业务规则、分支和待确认点 |
| 数据与验收 | 输入什么、得到什么，什么结果算完成 | 字段要点、输出、验收标准 |
| 汇总核对 | 理解是否准确，还有哪些遗漏 | 可确认的需求清单和文档草稿 |

每轮建议 2—3 个问题，不用固定长问卷。答案能从已提供资料确定时先给依据并请核对；缺少信息时提问。阶段只是整理顺序，用户可以回到任意阶段修改，跳过不会自动当作否定答案。

### 两条路线共用的设置

| 设置 | 选项 | 建议默认值 |
| --- | --- | --- |
| 输出用途 | 业务讨论、需求评审、开发交接 | 业务讨论 |
| 整理深度 | 简要清单、标准需求说明、详细规格 | 标准需求说明 |
| 关注重点 | 流程、权限、数据、异常、对接、性能与使用体验 | 流程、权限、异常 |
| 模型 | 工作台默认模型、已有模型列表 | 跟随工作台默认；每次任务保存实际使用的模型 |
| 提问节奏 | 少量关键问题、逐项详细核对 | 少量关键问题 |
| 输出语言 | 中文或用户指定语言 | 中文 |

详细规格只增加梳理字段和问题，不会让模型凭空补齐业务规则。模型切换影响后续运行，已有结果保持到用户主动采用新建议。

## 5. 主选项卡：对话

对话页承担访谈、解释、讨论和修改建议，结果在工作区中有对应条目。

| 消息卡片 | 内容 | 按钮与行为 |
| --- | --- | --- |
| 路线选择卡 | 快速整理、引导分析及简短说明 | 选择后进入对应流程 |
| 澄清问题卡 | 为什么问、已有依据、建议选项和自由回答 | 提交回答、暂时跳过、标记待确认 |
| 本轮结果卡 | 新增/修改的需求数、流程数、问题数 | 查看结果、逐项采用、继续澄清 |
| 修改建议卡 | 修改前后对照、涉及条目和可能影响 | 采用选中、不采用、补充要求 |
| 来源卡 | 引用资料名称、片段和定位信息 | 查看原文、回到对应问题 |
| 检查结果卡 | 冲突、遗漏、含糊或无法核实的内容 | 查看问题、标记不适用、补充依据 |
| 文档卡 | 文档名称、采用的数据版本、草稿或确认版本 | 查看、复制、导出、按要求修改 |
| 处理状态卡 | 实际阶段、错误原因、恢复入口 | 停止生成、重试失败步骤 |

建议快捷操作：整理需求清单、补充异常流程、检查权限遗漏、把本轮整理成文档。每个操作都展示作用范围；用户选中 REQ-003 后“补充异常流程”只针对该需求及相关流程。

“停止生成”停止本次后台任务或拒绝继续采用其返回内容；已经保存的草稿和上一版成果保留。模型无法中止网络请求时，显示“已停止接收本次结果”，不能虚报远端调用已取消。

## 6. 工作区选项卡：概览

概览让用户快速知道这次分析的目标、进展和下一步。

| 区块 | 字段 | 操作 |
| --- | --- | --- |
| 基本信息 | 名称、业务背景、问题、目标、适用人员 | 编辑、围绕此项讨论 |
| 范围 | 本次包含、暂不包含、外部依赖 | 添加条目、调整归属、记录理由 |
| 进展 | 已整理需求、已确认需求、待确认问题、待复核需求数量 | 点击数量进入带筛选的列表 |
| 待办提示 | 关键问题未回答、需求缺少验收条件、文档需要更新 | 直接跳转到对应条目 |
| 最近变化 | 最近采用的修改、最近确认版本 | 查看差异、打开版本 |

不显示缺少依据的“需求成熟度 93%”。若显示比例，明确是“已确认 6 / 10 条需求”等可计算数据。

修改目标或范围时，展示可能受影响的需求，用户决定调整哪些条目；助手不能直接删除不再符合新目标的需求。

## 7. 工作区选项卡：资料

### 页面组织

左侧或上方为资料列表，主区为原文预览与定位。资料行显示名称、类型、来源、添加时间、处理状态和引用数量。

| 输入方式 | 第一版 | 后续扩展 |
| --- | --- | --- |
| 手工输入、粘贴文本 | 支持，可命名和分段 | — |
| TXT、Markdown | 支持，检查编码和大小，解析后预览 | 增加批量导入与资料分组 |
| 会议纪要 | 可粘贴已有纪要并注明来源 | 从已保存会议任务中选取纪要/转写 |
| Word、文本 PDF、表格 | 第二阶段实现真实解析后开放 | 表格选页、列映射、页码定位 |
| 扫描件、图片 | 需 OCR 或视觉适配支持后开放 | 显示识别状态并允许核对 |
| 网页和知识库 | 需真实浏览器或检索路由后开放 | 保存取得时间、引用位置和快照 |

### 按钮与规则

- “添加资料”：选择已支持的输入方式；未接入的方式在规划中列出，正式界面不显示可用假入口。
- “查看原文”：定位到需求引用的段落；来源同时保留原文快照及段落标识。
- “重新整理此资料”：列出可能新增、修改、重复或冲突的需求，采用前不覆盖工作草稿。
- “编辑资料”：保存新的资料修订。既有需求仍指向旧修订，并标记来源有更新，供用户核对。
- “从本次分析移除”：取消其参与后续分析；已有引用保留当时片段和移除标记。彻底清除被引用原文需说明影响，并将相关需求改为来源缺失/待复核。
- “重复资料”：根据内容标识提示已添加，不重复产生同一批条目；用户可作为新版本保存。

解析状态分别显示待处理、处理中、可用、部分可用、失败。超出处理范围时说明哪些页或段落尚未处理，不把截断内容当作整份资料分析完成。

## 8. 工作区选项卡：需求清单

这是整个功能的核心页面。默认列表按模块分组，支持搜索、状态、优先级、类型、来源筛选。

### 默认列表列项

| 列 | 示例 | 说明 |
| --- | --- | --- |
| 编号 | REQ-001 | 稳定编号，删除后不重排其他编号 |
| 标题 | 员工提交报销申请 | 用具体行为命名 |
| 模块 | 报销管理 | 可手工调整分组 |
| 类型 | 功能 / 非功能 / 约束 | 分类可以编辑 |
| 优先级 | 必须 / 应该 / 可以 / 暂缓 | 助手可建议，用户确定 |
| 确认状态 | 待确认 / 已确认 / 待复核 / 暂缓 | 不与开发进度混用 |
| 来源 | 资料 2·第 4 段 | 点击定位，助手建议单独标识 |
| 待处理 | 2 个关联问题 | 点击打开相关问题 |

### 需求详情抽屉

默认展开标题、描述、角色、优先级、验收标准、来源、状态。其余字段分组折叠：

1. 业务信息：目标、触发条件、前置条件、正常步骤、结果。
2. 业务规则：判断条件、权限、异常、限制、关联规则编号。
3. 数据信息：输入字段、输出内容、校验要点、需要对接的对象。
4. 验收标准：场景、操作、预期结果；一条需求可包含多项。
5. 关联信息：来源、关联流程、依赖需求、相关问题、修改历史。

### 操作按钮

| 操作 | 行为 |
| --- | --- |
| 新增需求 | 手工填写最少字段，先保存待确认草稿 |
| 编辑 | 保留未保存草稿；采用前查看已确认内容的变化 |
| 围绕此项讨论 | 将稳定编号放入对话上下文 |
| 拆分 | 先预览新条目，采用后保留原条目的替代关系和来源 |
| 合并 | 先选择条目并预览；保留原编号到新条目的引用关系 |
| 确认需求 | 展示待确认内容与关联关键问题；通过业务校验后确认 |
| 暂缓 | 填写可选原因，移入暂缓筛选，不丢弃原文 |
| 移除 | 软移除，提供撤销或已移除筛选，显示相关文档/流程影响 |
| 批量操作 | 对明确勾选的集合调整模块、优先级或确认；提交前核对范围 |

筛选后的全选只选择当前结果。若所选条目在后台改变，确认操作要求重新核对，防止确认不是刚刚看到的内容。

### 一条需求的示例

| 字段 | 示例 |
| --- | --- |
| 编号 / 标题 | REQ-002：审批人退回报销申请 |
| 描述 | 审批人可以将申请退回给提交人，并填写退回原因 |
| 前置条件 | 当前申请处于该审批人可处理的审批环节 |
| 验收 1 | 审批人填写原因并点击退回，状态变为“待修改”，提交人可查看原因 |
| 验收 2 | 无审批权限的用户不能执行退回操作 |
| 待确认 | 原因是否必填；重新提交后从哪一级开始审批 |
| 来源 / 状态 | 访谈描述第 3 段；待确认 |

以上只演示字段和交互，示例规则不能直接写入用户实际业务。

## 9. 工作区选项卡：流程与规则

在一个子页内提供“业务流程 / 业务规则”两个视图切换，避免把所有业务对象挤进主导航。

### 业务流程

第一版采用步骤表：步骤编号、执行角色、动作、输入、输出、进入条件、下一步、异常分支、关联需求。

可用操作：新增步骤、插入步骤、调整顺序、添加分支、关联需求、检查断点、围绕流程讨论。这里的排序代表业务过程次序，不表示工作台已经实现自动执行这些步骤。

检查项：是否缺少开始/结束、分支是否没有出口、退回后如何继续、执行人是否不明确、步骤是否没有对应需求。检查结果进入待确认列表。

第二阶段可由同一份步骤和分支数据生成流程图。先支持查看和定位，复杂拖拽绘图单列后续范围。

### 业务规则

| 字段 | 示例 |
| --- | --- |
| 编号 | RULE-001 |
| 名称 | 报销金额对应审批层级 |
| 适用条件 | 申请金额属于指定区间 |
| 处理规则 | 采用对应审批路径 |
| 例外 | 特殊费用或代理审批是否适用，待确认 |
| 关联需求 | REQ-001、REQ-003 |
| 来源与状态 | 用户描述，待补充金额区间 |

金额阈值、审批层级、保存期限、性能指标等缺失时显示未确定，不自动填入常见行业值。权限矩阵、字段表可以作为本页的折叠区，基础版先做简单表格，详细规格逐步丰富。

## 10. 工作区选项卡：待确认

集中处理问题，避免答案散落在长对话里。

| 分类 | 示例 |
| --- | --- |
| 缺失信息 | 谁拥有最终审批权？ |
| 来源冲突 | 会议纪要说两级审批，现行说明说三级 |
| 表述含糊 | “尽快处理”具体指多长时间？ |
| 决策选项 | 退回后从第一步审批，还是回到原审批人？ |
| 影响复核 | 审批层级变更后，通知和权限是否也要调整？ |

每项包括编号、问题、为什么需要确认、已知依据、建议选项、影响的需求、是否阻止确认、状态及答复记录。

按钮：回答、查看依据、暂缓、标记不适用、重新打开。回答可选按钮或自由输入；“不确定”保留待确认，不当作已解决。是否阻止确认由具体业务依赖判断，并可由用户说明理由调整。

用户回答后，助手给出受影响条目的修改建议。只有采用建议或人工完成对应编辑，问题才进入已解决；若答案只是背景说明则保留问题。已经回答过的问题保留原答案，再次出现冲突时建立关联提示，不重复盲问。

页签徽标统计待回答/待处理问题；“全部已解决”只依据记录状态，不代表业务需求已获外部审批。

## 11. 工作区选项卡：需求文档

### 文档结构

默认“标准需求说明”包含：

1. 文档名称、分析范围、版本和状态。
2. 业务背景、问题和目标。
3. 本次范围、暂缓范围、约束与外部依赖。
4. 使用角色及职责。
5. 业务流程。
6. 功能需求清单及详细条目。
7. 业务规则、权限和数据要点。
8. 非功能需求与约束。
9. 验收标准。
10. 待确认事项与资料来源。
11. 修订记录。

“简要清单”只呈现目标、范围、需求和问题；“详细规格”展开字段、条件、异常与对接要求。不存在的数据明确留空或列为待确认。

### 顶部控制和操作

| 控件 | 行为 |
| --- | --- |
| 模板选择 | 简要清单 / 标准需求说明 / 详细规格 |
| 内容范围 | 全部当前需求 / 已确认需求 / 勾选条目 |
| 版本选择 | 当前草稿 / 某个已确认版本 |
| 生成或更新预览 | 依据指定数据修订生成；内容过期时提示待更新 |
| 调整表达 | 只修改选定章节的叙述，业务语义变化仍转为需求修改建议 |
| 复制 / 导出 Markdown | 导出当前所选版本，文件名包含标题和版本 |
| 打印 / 保存 PDF | 复用系统打印方式，显示打印预览；不是后台直接生成 PDF |
| 保存确认版本 | 检查所选范围、关键问题和验收条件，用户核对后生成不可变快照 |
| 版本记录 | 查看创建时间、范围、差异说明；旧版本可读、可导出、可恢复到新草稿 |

### 草稿与确认版本

- 讨论稿允许包含待确认和暂缓内容，并清楚标记；用户可以随时导出。
- 确认版本针对明确选择的范围。该范围内的需求必须已确认，关键问题已解决且验收条件齐全；其他范围的问题不阻塞本次有限范围确认。
- 保存确认版本记录本工作台中的确认事实，不等同于组织审批或相关部门签字。
- 修改已确认需求时，旧快照保留；工作草稿中的相关需求变为待复核，只有重新确认才能进入下一份确认版本。
- 恢复历史版本创建新的工作草稿，先显示将被替换的未保存内容；不会覆盖现有版本历史。
- 结构化需求是业务事实来源。第一版不开放与条目无关联的整篇自由编辑器；章节补充说明单独保存，重新生成时保留，避免文档和清单出现两套规则。

## 12. 主选项卡：轨迹

轨迹记录已经发生的操作与结果，便于解释需求如何形成。

| 事件 | 显示内容 |
| --- | --- |
| 添加/更新资料 | 名称、资料修订、时间、处理结果 |
| 发起分析 | 本次操作、输入范围、选定模型、开始时间 |
| 分析完成或失败 | 候选条目数量、失败阶段、是否已采用 |
| 回答问题 | 问题编号、回答来源、相关变更 |
| 采用修改 | 涉及条目、前后差异、发生时间 |
| 确认需求 | 所确认的需求与修订、操作时间 |
| 保存确认版本 | 版本、范围、需求数量、说明 |
| 导出 | 导出格式、所选版本、完成状态 |
| 停止/重试/恢复 | 对应任务和恢复结果 |

支持按全部、资料、分析、修改、确认、导出筛选。点击事件可回到相关条目或版本。模型内部推理不作为轨迹内容；错误与诊断信息只展示处理问题所需的简明说明。

## 13. 与会议纪要助手的联动

建议作为第二阶段优先项，先完成“从会议导入需求”，再考虑从会议侧新增跳转按钮。

### 需求助手侧入口

资料页 → 添加资料 → 从会议纪要导入 → 选择会议 → 选择内容 → 预览 → 导入。

可以选择会议概览、主要结论、行动项、待确认事项、完整转写。默认选择主要结论和待确认事项；用户可以调整。行动项先识别为任务或跟进事项，不自动视为软件功能需求。

### 导入后的关系

- 保存会议任务 ID、导入时间、内容指纹和所选内容快照；当前会议数据没有独立版本号时使用快照标识，不能伪造会议版本。
- 引用到转写片段时保留片段 ID 和实际时间信息。来源仍存在且有权限时，可跳转查看或回听；只有全文时不显示虚假时间戳。
- 分析结果修改仅作用于需求任务。原纪要更新后提示有新内容，用户选择是否导入差异。
- 原会议被删除后，已导入文本快照仍可解释需求来源，显示原任务已不可用；不能再回听已删除录音。
- 一个会议可以为多个分析任务提供资料。每次导入范围明确，不能默认把全部会议记录送给模型。

直接在需求助手内录音会牵涉音频上传、转写配置和任务归属，建议后续通过真实转写适配器复用，不在第一版另造一套语音设置。

## 14. 能力中心与岗位配置

### 新增能力的组织方式

建议能力名“需求分析”，先登记一个真实“需求分析服务”业务组件，提供资料整理、澄清问题、需求整理、检查、文档生成等明确动作。六个工作区页签是产品视图，不强行拆成六个可以任意拔除的假插件。

工作台模型与存储属于共享运行依赖。文件解析、会议导入等在具备真实执行适配后登记为相应组件或动作；首版可用动作和依赖以实现后的描述为准。

| 沿用的管理选项卡 | 需求分析能力中显示什么 |
| --- | --- |
| 概览与连接 | 组件是否完整、能力是否启用、模型是否选择、最近实际运行结果；保留共享页签名，具体状态用模型与服务描述 |
| 使用说明 | 适合的任务、支持的资料、提问方式、确认和输出规则 |
| 默认配置 | 默认模板、分析深度、提问节奏、默认模型来源；通过统一配置入口保存 |
| 关联组件 | 已登记的真实组件、动作、必需性、配置/详情入口、共享三栏编辑器 |
| 使用岗位 | 引用岗位、已发布版本、查看/编辑岗位入口 |

能力中心继续使用全部、收藏、待就绪、未使用、回收站分类。组件缺失草稿可以保存；发布时前后端都检查必需动作和兼容性。移除组件影响能力草稿，正在使用的发布版本继续按既有权限判定。

模型账户/密钥只在原工作台服务配置中管理。能力保存默认选择和策略，任务记录实际采用的模型与设置快照。展示“已选择模型”和“最近运行成功”两类状态，不把配置存在写成模型连通。

### 岗位接入和兼容

- 现有 builtin-analyst 保持身份、名称、颜色、图标、职责及用户编辑；能力绑定通过可追溯的新发布版本接入，旧发布版本及草稿保留。
- 已有普通需求岗位聊天仍按原历史会话打开，不强行转换为结构化任务。可由用户在新分析中粘贴内容，后续再提供明确的聊天导入。
- 新分析任务记录岗位及能力的实际发布版本，打开历史分析使用其绑定信息；任务执行同时检查当前启用/撤权规则。
- 执行页面按已登记的工作流适配器匹配真实能力，避免在公共渲染器中散落“只有这个固定角色 ID 才能执行”的分支。
- 自定义岗位装配该能力后，只有已验证的工作流组合才开放专用页面。跨岗位执行、复制和混合组合必须经过真实路由与授权验证。

## 15. 保存、确认、异常和恢复

### 三组状态分别显示

| 对象 | 状态示例 | 说明 |
| --- | --- | --- |
| 分析任务的业务阶段 | 草稿、待澄清、待确认、有确认版本 | 帮用户理解工作进展，允许回访 |
| 后台操作 | 排队、运行、成功、失败、已停止、中断待重试 | 表示一次模型/解析任务是否完成 |
| 需求条目 | 待确认、已确认、待复核、暂缓、已移除 | 表示业务确认，不表示开发完成 |

输入和工作草稿自动保存时显示保存中、已保存、保存失败。确认需求、保存确认版本、移除任务属于独立操作；自动保存不代表已确认。

### 会话生命周期

1. 使用现有新建入口时沿用“默认自由聊天”的已确认行为；用户选择需求助手后进入开始页。
2. 只打开页面或切换页签，不创建正式需求数据；选择路线后可以先保持临时行。
3. 用户输入非空业务草稿、保存资料或发送首条描述时，建立可恢复的需求记录，侧栏显示草稿或实际标题。
4. 切走空白临时会话按原规则清理；非空草稿保存，处理任务可以在后台继续。
5. 页面刷新和工作台重启后从服务端索引找回任务；输入未完成的内容尽量有本地缓存，服务端保存失败时明确提示。
6. 主标题栏“新建分析”创建另一个任务，旧任务保留；不使用含糊的按钮清空当前结果。
7. 通过“··· → 移除对话”显示需求任务的删除范围，用户确认后处理。后台确认成功后才移除侧栏行，失败保留入口并显示原因。共享资料原件与原会议记录不删除。

### 并发和故障

| 情况 | 应有行为 |
| --- | --- |
| 模型超时或格式错误 | 保留输入和旧结果，显示失败阶段；重试生成候选结果 |
| 返回结果缺少来源 | 保留为助手建议或无依据条目，不能标记为资料事实 |
| 运行时用户改了需求 | 返回结果带所依据的修订号；检测冲突并展示差异，不覆盖新编辑 |
| 同一按钮重复点击 | 后端按操作标识去重，避免重复条目与确认版本 |
| 工作台重启中断分析 | 标记中断，可从已保存输入重试；只读结果仍可打开 |
| 保存失败 | 显示未保存状态，保留本地编辑草稿；不能显示“已保存” |
| 能力被停用/移除 | 新模型处理被阻止；历史结果按既有策略可读，人工查看与本地导出保留 |
| 文档依据已经变化 | 显示“文档需更新”，导出前可更新或选择原确认版本 |
| 资料太大或只解析部分 | 列明已处理范围及剩余部分，用户选择分批继续 |

## 16. 技术实现的建议拆分

本节是开发设计建议，命名与接口在实施时结合现有结构确定。

### 前端

| 模块 | 职责 | 复用点 |
| --- | --- | --- |
| 需求会话容器 | 对话、需求工作区、轨迹及上下文输入 | 会议外层布局、岗位图标、状态卡、模型列表 |
| 六个工作区页面 | 概览、资料、需求、流程规则、问题、文档 | 工作台列表、弹窗、按钮、页签和主题变量 |
| 差异与确认面板 | 候选结果、采用修改、业务确认、版本恢复 | 共用弹窗、焦点、键盘与草稿保护方式 |
| 专用工作流登记 | 岗位/能力路由到实际视图 | 统一描述与适配器；共享修改回归会议路径 |
| 侧栏任务适配 | 把服务端需求记录映射为历史行 | 原会话布局和省略号菜单 |

避免整份复制 MeetingDemo 再修改名称。可以提取确有复用价值的消息卡、模型选择和任务状态组件，需求表格与确认逻辑独立实现；每次共享提取都回归会议助手。

### 服务端数据

| 对象 | 必要信息 |
| --- | --- |
| 分析任务 | ID、标题、模式、业务阶段、修订、时间、角色/能力发布版本、配置快照 |
| 资料及片段 | ID、类型、来源、资料修订、内容标识、段落/页码/会议片段位置、解析状态 |
| 需求 | 稳定 ID、编号、业务字段、来源引用、确认状态、当前修订、关联问题 |
| 流程和规则 | 节点、分支、规则、需求引用、确认信息 |
| 问题 | 编号、分类、依据、影响范围、答复、状态、是否阻断确认 |
| 修改建议 | 依据的数据修订、拟修改对象、前后差异、采用或拒绝结果 |
| 文档与确认版本 | 模板、生成依据、范围、正文、不可变业务快照、修改说明 |
| 运行和事件 | 操作 ID、真实状态、模型、错误、时间、用户可读事件 |

建议由独立 RequirementsService 负责校验、保存、模型调用和版本操作，复用工作台 llm 与认证。数据存放到现有 dsh-data/capabilities 下的独立 requirements 目录或等价存储，维持运行环境、源码和用户数据分离。

任务保存使用原子写入；确认和采用修改使用修订检查；索引可由持久任务恢复。文档快照和被引用来源保留一致性，不让模型直接覆写磁盘上的正式版本。

### 执行步骤

1. 接收明确的任务范围、操作、输入版本和角色/能力授权。
2. 收集相关需求、资料和回答，给来源稳定引用；不默认发送整个任务库。
3. 调用选定模型输出结构化候选结果。
4. 服务端校验字段、编号关系、来源存在性与引用范围。
5. 保存候选建议，用户采用时再更新工作草稿并记录差异。
6. 业务确认与确认版本由确定性校验处理，模型不能自行将状态改为已确认。

资料中的文字只作为待分析内容，不能借资料内容修改工具权限或触发外部操作。长资料分段处理并保留覆盖范围，处理量限制和分批入口在实施时按已有模型能力确定。

## 17. 推荐实施批次与验收

| 批次 | 交付范围 | 完成标准 |
| --- | --- | --- |
| 第一批：界面与任务基础 | 三个主选项卡、六个子页、两条路线、文本资料、手工需求、保存重开 | 用户能够手工建立完整需求说明，真实保存与恢复 |

前三批合起来作为第一版正式可用范围。阶段性界面可以用于讨论，但模拟数据不得被标记为真实分析完成；每批验收如实说明后端和模型是否接通。

### 核心验收场景

1. 只有一句业务想法时，引导提出关键问题；回答后已有信息不被反复询问。
2. 粘贴完整描述后，生成需求与问题，来源能定位到具体片段。
3. 拆分或合并需求后，原引用及替代关系仍可追溯。
4. 人工编辑过的内容遇到重新生成时，以差异建议呈现。
5. 未解决关键问题的需求不能被直接确认；讨论稿仍可导出。
6. 确认版本保存后继续修改，旧版本与旧导出内容保持可读。
7. 刷新、切换会话、重启后，资料、条目、问题、草稿、版本可恢复。
8. 模型失败、任务停止、重试和并发修订不会产生假成功或重复需求。
9. 移除会话、移除资料、移除组件分别显示真实范围，不影响其他任务或原会议。
10. 能力组件缺失草稿保存重开、发布阻断、补回、重复添加、发布版本执行隔离通过验证。
11. 岗位卡片选择、顶部入口、新建默认自由聊天、历史岗位恢复继续符合已确认行为。
12. 会议快速/引导流程、模型选择、资料核对、历史结果、浏览器共享管理回归通过；覆盖窄屏、深浅主题与键盘操作。

## 21. 会话内返回分析方式选择页：讨论方案（2026-09-29）

### 21.1 用户反馈与核实

用户提供第一版实际界面的两张截图，明确要求：点击右上角现有“新建分析”后，应在原来的对话里回到第二张图的方式选择状态，不直接新增对话；按钮命名也需要重新设计。本轮先给方案讨论，尚未授权实施本轮修订。

源码核实：RequirementsAssistant 的该按钮调用 onReset，apply.tsx 将其连接到 startFreshChat(effectiveRole)，因此会切换至新临时会话。两张方式卡只在没有 task 时显示，卡片点击 begin 又立即调用 ensureTask，导致只选方式也会创建正式需求记录。需要分开管理页面所处视图、所选分析方式和业务记录。

### 21.2 推荐入口与页面

| 所在位置/状态 | 建议显示 | 建议行为 |
| --- | --- | --- |
| 工作状态右上角 | 分析设置、切换分析方式 | 后者在当前会话的对话页展示两张方式卡；左侧选中行、当前记录和标题保持 |

| 对话中的方式状态 | 当前方式：引导分析/快速整理 | 移除重复的直接切换按钮，统一通过顶部选择入口操作 |

推荐按钮名“切换分析方式”；“返回入口”可作为用户偏好的更短备选。避免“重新分析/重新开始/重置”，它们容易让人理解成重跑或清空。两个处理方式本身先保留现有名称。

### 21.3 两张卡片与已有内容

- 快速整理：已有业务描述、会议纪要或需求初稿，优先整理需求清单和待确认问题。选择后显示资料入口与整理操作；有资料时可以直接使用或补充，不强制重新上传。
- 引导分析：从目标和当前问题出发，通过问答逐步明确流程、范围与验收。选择后进入当前会话的对话区；已有内容作为后续提问的依据。
- 卡片点击只选择接下来的工作方式，不发送消息、不自动调用模型、不生成新任务、不覆盖已确认内容。
- 已选方式标记“当前使用”。再次选同一方式直接回到工作视图；选择另一方式后提示“已切换为……，当前内容已保留”。
- 输入框沿用现有内容。未选择方式直接发送时按原方案默认引导分析；已选方式时使用当前方式。添加资料会先进入资料编辑，确认保存后再持久化内容。
- 已有内容的选择页显示“继续处理当前需求，已有资料和结果已保留”，并提供返回对话。需求工作区和轨迹仍可打开；进入工作区后返回对话，保留本会话最近的对话视图。
