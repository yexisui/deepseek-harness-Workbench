## 已交付

设置中新增“Skills 技能”，复用原技能模块与插件管理入口。支持 SKILL.md、完整文件夹和 ZIP 导入，多技能勾选、全局 / 当前会话项目范围、同名更新或另存副本、搜索分类、启停、自动选用设置、详情与资源清单、ZIP 导出、上一版本回退、移除与恢复。原始导入文件不改动，脚本和资源随包保留；回退及恢复保持停用。

插件独立入口与能力中心共用 InventoryTree 和 EnableSwitch。全局开关按精确条目 ID 修改配置，支持热更新时实际应用，否则显示待重启。普通本地预设只影响新会话；内置预设、岗位生成预设、条件条目和基础管理服务解释不能切换的原因。既有能力依赖检查保持。

Skills 总开关同时控制新的自动和手动调用；已进入对话上下文的说明不能撤回，不强制中断正在执行的任务。导入不会运行脚本、安装依赖，或自动转换 Codex 专用工具。未纳管旧技能保留原管理行为。新增 Skills 不等于新增可发布能力，不改变岗位授权和执行路由。

管理资产放在 DSH_HOME/skill-management，运行副本放在 DSH_HOME/skills 或项目 .dsh/skills。格式、路径、大小、同名冲突、外部改动、过期预览和并发版本均有校验。文件和记录分别原子落盘，尚无数据库级跨文件崩溃恢复保证。

### 需要优化的地方

1. **优先级最高：补齐岗位技能绑定和运行时授权。** 岗位模型只有 capabilities，没有 skills；岗位编辑库只展示能力。技能全局启用无法赋予岗位调用权，即使职责中写了技能名称也会被拒绝。需让岗位显式选择技能版本，并让运行时只加载已授权技能，不放开全部全局工具。
2. **实际失败时定位技能或插件环节。** 不新增依赖检测步骤，不把预检查通过作为运行条件。直接执行实际请求；仅当某环节确实导致功能不可用时，说明出错环节和已知原因。
3. **模板资源缺少直接查看入口。** 详情能看 SKILL.md，但其他资源只显示文件名，没有正文预览。建议增加资源文件浏览与文本预览，并提供从技能详情跳转岗位配置的入口；是否允许在线编辑应与版本、保存和回退统一设计。
4. **可选样例试运行。** 如提供试运行，用户选择岗位并输入样例后直接执行，不经过额外检查环节；正常时仅返回任务结果，不展示检测通过、就绪或运行成功提示。实际功能不可用时才提示出错环节。试运行不能成为日常运行的前置条件。

以上为建议，未在本轮改造生产代码。用户随后明确取消岗位检测环节，原依赖预检和多阶段正常状态提示建议作废。后续优先补齐技能绑定和实际调用，遵守下述运行反馈要求。
