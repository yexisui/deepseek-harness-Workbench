## 实施范围

在 `deepseek_harness_desktop/packages/dsh-client-ui-plain-chat` 中加入一个仅前端存在的“会议纪要助手 · 界面演示”岗位入口。新对话中的设置卡片、岗位选择器和主区左上角岗位卡片共用选择状态。选择该岗位时，沿用工作台外层容器，在对话区域展示“对话 / 轨迹”页签、消息流和输入框，以及快速生成与引导整理两条路线。已有会话、自由聊天和其他已发布岗位继续使用原 `ConversationRoot`，未修改后端岗位记录、能力权限、工作区或会话数据。

演示路线支持选择本地 MP3/M4A/WAV 或示例录音。浏览器只取文件名，不读取或上传音频内容。模拟处理后显示固定样例转写与纪要；引导路线可修改样例转写，再确认生成。纪要卡片提供固定规则的简短调整、查看转写与复制。界面明确标注“UI 演示”和样例性质，真实转写、模型生成、音频回听与后端会话持久化留待后续接入。

## 2026-09-23 追加修复

用户指出左侧“聊天”分组旁的 + 无法新建对话，并要求每次新建对话默认自由聊天、重开历史对话时显示该对话原先选定的岗位。核查发现上游 `WorkspaceBrowser` 对未分组“聊天”的 + 按钮没有执行新建操作，且该按钮不经过顶部“新会话”入口。现只为该按钮接入与顶部入口相同的新建动作；两者都会清空未发送的新对话草稿并选择自由聊天。真实工作区分组的 + 仍走原工作区新建逻辑。

历史会话左上角按该会话保存的 `agentPreset` 识别岗位，并采用对应已发布版本的名称、颜色和图标；修改用于下一次新对话的岗位选择或岗位草稿，不会改变历史会话显示和已有会话配置。尚未发送消息的会议纪要 UI 演示仍属临时新对话，未创建可在历史列表重开的真实会话。

追加修复重新通过 31 项界面测试、类型检查及 client 构建，五个变动文件已同步正式链接包并核对哈希一致。追加修复前的版本备份位于 `<SECONDARY_WORKSPACE>\meeting-assistant-integration\backup-before-plus-fix-20260923`。运行中页面仍需重新加载，实际视觉与点击体验待用户验收。
