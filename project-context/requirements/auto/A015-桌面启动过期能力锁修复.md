# A015 桌面启动过期能力锁修复

> 协作迁移说明（2026-10-10）：本文件保留历次方案与执行记录；当前状态以[事项台账](../../PEFR_PLAN.MD)及本文件最新记录为准。旧版本界面、发布流程和本机路径不自动成为现行要求。`<WORKBENCH_ROOT>` 表示克隆后的工作台根目录，`<SECONDARY_WORKSPACE>` 表示作者本机隔离验证目录，后者不是协作开发前提。


- 记录来源：助手自动记录；用户于 2026-09-24 报告工作台无法启动并要求检查。
- 创建与更新：2026-09-24
- 状态：启动已恢复；桌面日志显示 GUI loaded，能力数据锁由当前运行的 Node 进程持有。

## 原因与依据

`desktop-state/logs/dsh-host.log` 显示主服务在加载 `workbench-capabilities` 时退出，错误为“能力数据已由另一个服务锁定”，随后桌面窗口因 3082 端口无服务而显示连接失败。`dsh-data/capabilities/writer.lock` 保存的 PID 为 17524，时间为 2026-09-23T06:18:50.961Z。检查时该 PID 已属于钉钉，其启动时间为 2026-09-24 09:00:11，晚于锁文件写入时间。旧能力服务已退出，Windows 后来复用了相同 PID；原锁逻辑只检查 PID 是否存在，因此误判为活动服务。没有证据表明前端会议纪要包导致本次失败。

## 修复

更新根目录 `start-desktop.ps1`：启动前读取能力数据锁的 PID 和写入时间。只有明确查到原 PID 不存在，或当前同 PID 进程的启动时间明显晚于锁时间时，才在再次核对锁内容未变化后移除过期锁。若进程与锁时间相符，保留锁并继续由能力服务阻止重复写入；查询权限或锁状态不明时也保留锁。时间戳直接从原始 JSON 的 ISO 字符串解析，以避免 Windows PowerShell 自动转换 JSON 日期时丢失时区并误删活动锁。

执行前已把原启动脚本和过期锁备份到 `<SECONDARY_WORKSPACE>\deployment\startup-recovery-20260924`。本次未删除或改写 `state.json`、岗位配置及会话数据。

## 验证

- 新脚本通过 PowerShell 语法解析，正式文件与工作区修订版 SHA-256 一致。
- 运行正式启动脚本后，输出确认移除过期 PID 17524 的锁；随后桌面日志出现 `GUI loaded`。
- 新 `writer.lock` 由当前 Node 进程 PID 41764 持有；该进程在检查时仍运行。
- 在 Windows PowerShell 5.1 下复核：当前活动锁的进程启动时间早于锁写入时间，修正后的条件判定为“保留活动锁”；脚本语法解析通过。未为此再次启动第二个桌面实例。
- 能力 `state.json` 的大小与修改时间保持原值。未验证模型请求或用户界面内所有功能。
