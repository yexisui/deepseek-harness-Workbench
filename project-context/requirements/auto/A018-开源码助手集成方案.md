## 1. 新方案结论

建议以 **OpenCode 作为本地代码执行引擎，封装成一个独立的“代码助手”模块，嵌入开发助手**。模块拥有自己的界面、会话、文件工具、执行进程和数据目录；模型通过宿主接口调用工作台已配置的服务。

优先选择它，是因为它已经提供相对完整的编码代理和独立服务接口，适合整体封装。新方案不再以改造旧 developer.ts 的 JSON 执行循环为中心，也不受旧四选项卡设计限制。既有源码和用户数据在本轮不删除，旧实现仅保留历史可读性；后续替换入口时另做必要迁移。

| 硬要求 | V2 的具体定义 |
| --- | --- |
| 开源 | 引擎、嵌入界面、宿主适配和本地依赖均采用有明确开源许可的实现；新增适配源码、构建与打包脚本随项目维护 |
| 功能离线 | 安装、启动、资源加载、文件读写、搜索、差异、命令执行、日志和会话存储不依赖互联网或第三方账号 |
| 模型复用 | 只使用工作台已有模型服务，不新增模型平台账号、API Key 配置页、本地模型部署或显卡要求 |
| 独立模块 | 单独工程、安装包、数据目录、生命周期和接口；不依赖旧开发助手执行器的内部状态 |
| 嵌入使用 | 在开发助手内部使用模块面板，不要求用户另开网站、独立客户端或 VS Code |
| 开发实用 | 能读项目、写代码、改多个文件、修 Bug、补测试、跑检查、看差异并继续任务 |

这里的“离线”不表示现有云端模型在断网时仍能推理。模块自身无云端功能依赖，模型的联网条件由已有工作台模型服务决定；本方案不重新选模型。

技术依据：[OpenCode Server](https://opencode.ai/docs/server/)、[JS/TS SDK](https://opencode.ai/docs/sdk/)、[自定义 provider](https://opencode.ai/docs/providers/#custom-provider)。

## 3. 独立模块怎样嵌入

模块逻辑名称建议为“代码助手”，工程名暂定 dsh-code-assistant。开发助手提供一个嵌入位置和通用宿主接口；模块负责完整编码流程。

整体关系：**开发助手入口 → 代码助手模块面板 → 模块控制层 → 本地 OpenCode 服务 → 本地项目文件与命令**。模型请求单独走 **本地模型桥接 → 工作台已有模型服务**。

| 部分 | 所属 | 职责和边界 |
| --- | --- | --- |
| 模块面板 | 代码助手模块 | 项目文件、代码与差异、任务对话、执行输出；本地打包资源，复用宿主公共样式 |
| 模块控制层 | 代码助手模块 | 项目绑定、会话映射、流式事件、权限请求、任务停止和错误状态 |
| OpenCode 运行服务 | 模块管理的本机进程 | 执行编码代理；仅监听回环地址，认证由宿主生成和管理 |
| 模型桥接 | 通用宿主适配 | 把引擎请求映射到已有模型路由，不把供应商凭据交给前端或引擎持久化 |
| 本地运行依赖 | 工作台 external-tools | 引擎及实际需要的 Git、Shell、搜索工具或语言服务；使用登记路径，不依赖用户额外全局安装 |
| 会话与日志 | 模块独立数据域 | 放在 dsh-data/code-assistant 下；停止、卸载模块不删除用户项目和历史任务 |

建议模块接口只覆盖：打开/释放面板、绑定项目、创建/继续任务、发送指令、订阅事件、停止、读取文件与差异、响应权限、查看健康状态。具体接口命名在实现时确定，不能把这些建议名称当成当前宿主已经具备的 API。

安装方式优先采用工作台插件机制注册独立宿主服务和前端面板，并通过统一能力描述关联到开发助手。现有一次性外置能力脚本不能直接等同于支持持续运行、流式事件和面板挂载的模块；如缺少通用挂载能力，补充这一层宿主接口即可，不把新模块逻辑继续塞入旧开发服务。

模块只有通用宿主依赖。离开开发助手专属页面后，应能由测试宿主装载、使用本地模型测试替身运行；这用于证明边界独立，并不要求给用户新增一个独立软件。

本地子进程用于模块生命周期管理，不自动构成文件或网络安全沙箱。项目范围、权限、外部修改冲突与停止子进程仍需实际实现并测试。

## 4. 第一版必须提供的开发功能

| 功能 | 对开发者的实际帮助 | 验收结果 |
| --- | --- | --- |
| 项目阅读与搜索 | 查文件、查实现、解释模块和错误位置 | 回答能定位实际文件和代码，搜索由本地工具执行 |
| 编写与修改代码 | 新建功能、修 Bug、多文件改动、小范围重构 | 实际文件发生对应修改，保留原有无关内容 |
| 编写测试 | 为功能或修复补测试用例 | 测试文件可审阅，并能交给项目测试工具执行 |
| 执行检查与修复 | 运行本地测试、Lint、类型检查或构建，再处理失败 | 日志和退出码真实；失败反馈能进入下一轮开发 |
| 代码与差异阅读 | 查看文件、修改前后内容，围绕选区继续提问 | 文件与变更同步刷新，用户未保存编辑不被覆盖 |
| 本地 Git 操作 | 看状态、暂存选定文件、审阅后本地提交 | 提交内容和预览一致；不自动推送或改分支 |
| 变更审查 | 检查当前差异中的问题并解释位置 | 默认只读，给出具体文件依据，不自动发远程评论 |
| 任务继续与停止 | 重开任务继续开发，查看历史执行结果 | 记录可回读；停止作用到实际任务及相关子进程，不重放旧命令 |

模块界面建议采用一个工作区：左侧项目与文件，中间代码/差异，右侧任务对话，下方按需展开执行输出。与旧四选项卡方案无继承关系；仍使用工作台统一图标、控件、主题和窄屏规则。交互控制保持简单：项目、当前模型、只读/允许修改、发送、停止、差异和运行结果。

代码编辑与差异展示建议采用 [Monaco Editor](https://github.com/microsoft/monaco-editor)，采用 MIT。它作为模块内部组件随包提供，JavaScript、workers 和字体全部本地加载。Monaco 不是 VS Code 扩展宿主，不承诺可以直接安装任意 VS Code 插件。

语义能力按实际交付的语言服务启用。首版先覆盖本项目相关的 JavaScript/TypeScript；其他语言仍可文本搜索和编辑，符号跳转、诊断或重命名不能在缺少相应语言服务时冒充可用。无需在第一版叠加 Tabby、Serena 或多代理团队。

## 5. 怎样兑现“功能离线”

OpenCode 支持本地运行，但上游默认配置不能直接当成离线交付版。需要把发布版本中的所有运行资源准备好，并逐项处理下表。

| 检查项 | 方案要求 |
| --- | --- |
| 安装和首次启动 | 完整离线包内包含锁定依赖；不能在首次使用时运行 npm/npx/bun 下载 |
| 模型目录 | 使用宿主提供的本地模型清单；关闭远程模型目录拉取 |
| 更新检查 | 关闭启动时更新及更新提示请求；仅通过工作台已有离线部署流程升级 |
| 账号与 provider | 只启用宿主模型桥接 provider；无 OpenCode 账号登录、订阅或云端授权步骤 |
| 插件和技能 | 只加载明确随包交付的本地内容；禁止隐式联网安装第三方包、远程 MCP 或个人全局配置引入的云服务 |
| LSP 与格式化工具 | 所需程序预置并登记；关闭自动下载，缺少依赖时显示真实状态 |
| 界面资源 | 无 CDN、远程字体、在线编辑器和网页壳依赖 |
| 遥测与分享 | 核对锁定源码及依赖，取消遥测、自动分享和外部状态上报 |
| 网页与远程仓库功能 | 本版不提供联网搜索、抓网页、自动 pull/push 或远程 PR 功能 |
| 项目构建依赖 | 使用项目已有依赖或用户准备的离线缓存；缺少依赖时明确说明，不能静默联网补装 |

官方 CLI 文档列出了关闭自动更新检查、模型目录拉取、默认插件和 LSP 下载的开关；锁定版本源码也含默认插件和语言服务下载相关控制。它们是实施依据，不是仅设置几个开关就已保证离线。[CLI 环境变量](https://opencode.ai/docs/cli/#environment-variables)、[v1.19.3 runtime-flags](https://github.com/anomalyco/opencode/blob/v1.19.3/packages/opencode/src/effect/runtime-flags.ts)。

配置存在全局、项目及内联等合并来源，因此模块须使用独立配置与数据位置，并检查项目配置不会重新启用云服务。外部插件加载器也存在依赖准备路径，运行时不得依赖它联网补齐。[配置来源](https://opencode.ai/docs/config/#precedence-order)、[锁定版本插件加载实现](https://github.com/anomalyco/opencode/blob/v1.19.3/packages/opencode/src/plugin/index.ts)。

离线可用与阻断任意项目脚本外联是两种不同保证。模块交付必须证明不依赖互联网，且自身没有非模型外联；若要求运行任何用户代码也强制不能联网，则需另加经验证的操作系统隔离，不能把普通子进程和工具权限规则当成网络沙箱。

## 6. 模型只对接现有工作台

模块面板读取工作台已有模型列表与默认选择，用户不用重新填 Key。OpenCode 仅访问本机模型桥接端点，供应商请求仍由工作台原模型服务发出。标题生成、上下文压缩等辅助模型调用也必须走同一个桥接，不能偷偷回退到上游默认模型。

这个桥接是协议适配，不是另建模型服务：需要保留多轮消息、工具定义、工具调用标识、结果回传、流式事件、取消和必要的上下文参数。当前 workbenchText 只把文本片段拼成字符串，因此不能直接拿它代替完整工具调用协议；应在宿主现有 llm 服务层进行窄适配。无需重新选模型或新增模型部署方案。

现有模型对某项工具协议的兼容性仍须验证。不可用时报告真实原因，不能以删除工具调用、静默切换供应商或增加一套凭据配置来伪装成功。模型无法访问时，模块的文件、差异、日志和历史查看仍可用，生成任务显示模型服务暂不可用。

OpenCode 支持通过自定义 provider 指定兼容接口，是该桥接路线的上游依据；本项目的桥接尚未实现。[自定义 provider 说明](https://opencode.ai/docs/providers/#custom-provider)。

## 7. 打包、维护与验收

建议工程放在 deepseek_harness_desktop/packages/dsh-code-assistant；前端、后端适配、测试和打包说明在同一模块维护。OpenCode 本机运行文件放在 external-tools/opencode，其他必需程序先复用已登记依赖，缺少时再登记；业务数据放入 dsh-data/code-assistant。以上均为拟议路径，本轮没有创建运行目录。

对用户交付的是一个“代码助手模块”及其统一安装入口。物理上模块源码、公共运行工具和业务数据按工作台规范分别存放；不把公共二进制重复装进每个能力 ZIP。源代码、构建脚本、上游版本/修改清单和第三方许可证进入 Git；完整程序及依赖进入 offline-delivery 离线包。卸载模块保留项目、凭据和任务资料，不要求用户管理内部发布版本或备份流程。

Windows 原生运行优先；官方虽允许 Windows 直接运行，但推荐 WSL。因此中文路径、Git Bash/Shell、进程停止和干净机器启动都要验证，不能把原生可用当作已验收，也不默认要求用户安装 WSL/Docker。[官方 Windows 说明](https://docs.opencode.ai/docs/windows-wsl/)。

| 验收组 | 操作 | 通过条件 |
| --- | --- | --- |
| 干净环境离线安装 | 清空下载缓存，阻断公网，只提供完整离线包 | 可安装、首次启动和打开模块；无依赖下载要求 |
| 功能断网验证 | 使用本机确定性模型测试替身驱动文件工具和多轮任务 | 读取、搜索、编辑、检查、差异和会话恢复完成；只证明工具链，不冒充真实模型质量测试 |
| 真实模型桥接 | 仅允许工作台模型服务访问其配置端点 | 使用原模型完成多文件修改与测试修复；代码助手进程无其他外联 |
| 外联核对 | 记录模块及相关进程的 DNS/网络活动，核对启动与运行路径 | 无模型目录、更新、遥测、插件/LSP下载等非模型外联尝试；发现一项就修复并复测 |
| 原有代码保护 | 带未提交修改、外部编辑和部分暂存的合成项目 | 不覆盖无关改动；真实差异与提交范围正确 |
| 生命周期 | 长任务停止、模块禁用、重新启动、任务重开 | 相关进程正确结束；历史存在；停止动作无命令重放 |
| 独立嵌入 | 测试宿主加载模块，再在开发助手挂载 | 不依赖旧开发任务内部结构；停用模块不影响其他岗位 |
| 统一管理与交付 | 添加/移除/补回、保存生效、主题窄屏、已有安装复用及修复 | 管理方式一致；完整离线包和校验文件可交付 |

“保证离线”应以以上实际安装、运行和外联证据为依据。本轮仅完成文档与部分源码核查，尚不能宣称候选发行版已经通过这些测试。

## 8. 分阶段安排与本轮状态

实施顺序建议为：先验证离线封装和宿主模型桥接，再完成模块内开发功能与界面，最后接入统一管理并交付离线包。这个顺序不继承上一版改造旧执行器的步骤。

| 阶段 | 工作内容 | 进入下一阶段的条件 |
| --- | --- | --- |
| A：核心可行性 | 固定 OpenCode 版本、整理本地依赖、接宿主模型、核查所有外联 | Windows 干净环境启动、多轮工具调用、停止和无非模型外联通过 |
| B：独立模块 | 模块生命周期、会话、项目工具、原生嵌入界面与代码差异 | 多文件开发、测试修复、重开及外部编辑冲突处理通过 |
| C：工作台交付 | 插件/能力注册、岗位挂载、离线安装/修复、相关回归 | 安装包、许可、校验清单和验收证据完整 |

本轮不复用上一版 6–10 个工作日估算。独立模块需要新的宿主挂载、模型协议和离线运行验证，完成阶段 A 后才有可靠的后续工作量依据。

本次确定的设计边界：模型沿用工作台；功能本地运行；模块独立封装；旧方案不再约束。OpenCode 为推荐实现，仍待用户确认实施。没有安装引擎、模型或插件，没有删除旧功能，没有修改业务源码、配置、启动服务或制作安装包。

离线阅读版使用同一 Markdown 生成，沿用 styled-html-report 模板。本轮进行静态内容、章节与资源引用检查；前轮浏览器访问限制仍未解除，不以静态检查代替浏览器交互验收。
