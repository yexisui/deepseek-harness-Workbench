## T034 安装环境缺项修复（2026-10-10）

### 原因核实

现有工作台保留早期 M001/M002 的安装布局：桌面 start-desktop.ps1 通过 Get-Command node.exe 使用系统 Node；DSH、pnpm、Electron 和定制插件已经存在且版本正确。便携部署所需 runtime-node、Web/Build 启动入口以及 deployment-selection.json 均不存在。缺项来自早期系统 Node 启动流程与后来便携部署脚本的路径假设不一致，没有发现配置丢失；不能据此推断历史上发生过文件删除。

原脚本只在完整 Deploy 中安装 Node，而 Check/Build/Desktop/Web 固定读取 runtime-node，缺少针对已运行旧环境的单独补齐入口。直接全量 Deploy 会重新安装依赖和登记 profile，不适合作为此次最小修复。

### 实施

- deploy.ps1 增加 Bootstrap：在原部署锁内安装/复用便携 Node/npm，只生成缺失入口并执行完整安装检查；不调用依赖安装、profile 安装、业务构建或插件注册，不覆盖已有部署选择。
- Write-Launchers 增加 MissingOnly；Bootstrap 保留现有启动脚本及过期锁处理。正式补齐启动网页版.cmd、重新构建.cmd。
- start-desktop.ps1 优先选择本地 runtime-node/node.exe，旧环境尚未补齐时继续使用系统 Node；DSH_HOME 保持同一工作台，原锁清理逻辑保留。
- 官方 ZIP 下载和 SHA-256 校验成功；首次在较深测试路径解压失败，缩短为工作台根 runtime-node-stage-随机短标识 后，在 Windows PowerShell 5.1 同类路径重测成功。新增暂存目录忽略规则，不提交 Node 或缓存。
