# 需求检查

基于用户提供的需求或明确指定的资料，检查实现前需要澄清的缺口。

使用 [评审模板](references/review-template.md) 组织结果。重点核对：谁能操作、什么条件下操作、状态如何改变、失败时怎么办、怎样判断完成。

每个问题引用资料中的具体表述，区分“明确冲突”和“尚未说明”。不要自行决定缺失的产品规则。按影响选出最多三个最值得优先确认的问题；如果信息充分，可以没有问题。

如果用户提供网页资料，且当前岗位已授权浏览器读取工具，可先使用已提供的浏览器技能加载相应工具再读取。没有授权工具或无法访问时，请用户提供正文，不把导入本技能视为新增工具权限。

输出采用中文。用户只要求评审时，不改代码、不提交表单、不创建外部任务。
